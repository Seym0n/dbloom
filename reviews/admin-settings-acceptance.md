## Findings during the work
- **Audit field name.** The first live run showed `"key": "[redacted]"` in the audit row: the redaction treats a field named `key` as a secret. The fields are now named `setting` (writer, clamp report, tests). Without the live spec this would have shipped with unreadable audit rows.
- **Who changed it.** The page printed the user id of the last change. The service now maps ids to display names (`setup` and `cli` stay as they are, a deleted user shows as "a removed user").
- **Wizard rows.** The first-run wizard stores its site values in the same table, so those settings show "Set here" from the start. The specs compare single keys.
- **Saving an empty text** stores an empty override and shows "Set here"; "Reset" returns to the default. Both have the same effect.
- **Site notices refresh.** The banner and maintenance line of the settings page came from a cached session read and did not update after a save; the page now refreshes it (found by the mock-layer spec).
- **Forcing maintenance with a restart.** A session survives a restart, but the browser page of the old session was refused `session_ended` on its first call; the live spec signs in again in a new context after a restart (as the exposure spec does). Cause not examined; it is a property of the fixture's reused browser state, not of the settings code as far as seen.
- **Registry size.** The map and the spec said 41 keys; the registry has 36 (plus the four new ones, 40 in all, 39 on the page because `loginAutofocus` is a per-user preference).
- **Existing audit event** `settings.clamped` was reused instead of the spec's `settings.clamp`.
- **Timing flake.** `tests/sql-run.integration.test.ts` ("SLEEP is stopped ... thread gone") failed in three full runs and passes alone (84 of 84). It checks that no `SLEEP` thread is left on the shared test MySQL while other files run; not touched by this module.
- **`vite build` `EBUSY`** again several times in a row; it passed after waits of 30 to 60 seconds.

## Not done or not run
- Settings of target policy, import and export, history and display are not on the page (`SPEC/FUTURE.md`, FU-settings-ext); export and import of settings (FU-settings-transfer); per-setting operator limits (FU-settings-per-key-limits).
- Step-up on every write is uniform (the banner included); the step-up set, the lockout warning with the number of affected users for other settings, and the auto-revert are `admin-protect`.
- Direct mode has no settings page, no maintenance mode and no banner.
- Two administrators editing at once is not exercised live.
- The administration plane is deferred: administrators reach the page from any address (the exposure page says so).
