## 2. Most important defect classes

1. SQL built by string concatenation or interpolation (SEC-DTB-004/005, FR-PLG-032, SEC-IOX-096, FR-IOX-051, SEC-SRV-004/012, FR-SRV-017/022/074). Eleven of the 25 rows. DBLoom answer: SEC-TGT-051, 115, 116, 117 and 119 (central quoter, schema validation, existence check, lint in CI). The only real choice is how much free-form SQL fragment input to allow (the one NOD row).
2. Authentication and second-factor weaknesses that fail open or are not enforced (FR-SAU-059, SEC-SAU-306, FR-SAU-064, FR-SAU-045, SEC-SAU-206, FR-SAU-006). DBLoom answer: SEC-TGT-011/014/017/021/040, NFR-TGT-090, DEP-TGT-091, NFR-TGT-093 (fail closed). Gap found: single-use challenges and generic error messages are not stated in the SEC-TGT text, and the scope triage (18, SEC-SAU-306) says SEC-TGT-011 covers them, so add the wording proposed above.
3. Missing central enforcement: no router-level authorisation and CSRF on POST only (SEC-SAU-321/324), plus hand-written security arithmetic (CIDR). DBLoom answer: SEC-TGT-060/136, SEC-TGT-042/134, SEC-TGT-128. These must be structural (middleware, registry, library), not per-handler discipline.

## 3. Regression tests DBLoom should have

- Injection corpus: for every endpoint, send quote, backslash, `;`, comment markers, `ANSI_QUOTES` mode, oversized and negative numbers, unknown names (binlog, sort, plugin, variable, table); expect rejection before any SQL is sent. Include the three named in SEC-TGT-119 (binlog log, process-list sort_order, plot limit).
- CI lint: a deliberately concatenated SQL string fails the build (SEC-TGT-117); a handler without an input schema fails the build (SEC-TGT-115).
- Import: terminators with special characters; multibyte text decoded with chunk boundaries at every byte offset.
- CIDR: high-bit prefixes (/1, /8, /9, /31), IPv4-mapped IPv6, invalid entries rejected at save.
- WebAuthn: wrong signature, replayed response, counter not increasing, forged Origin/Host, missing library at start-up, library error text never reaches the response.
- Challenges and codes (WebAuthn, TOTP, recovery codes): single use, expiry, session and purpose binding.
- Login: pending-2FA session cannot reach any other API or open a target connection; every rejection path writes one audit entry; backoff grows and cannot be bypassed with spoofed forwarded headers.
- Authorisation and CSRF: route enumeration against the endpoint registry (401/403 matrix); no state change on GET; POST without token or with a foreign Origin returns 403.
- Copy-user: look-alike user and host combinations with column grants.
- Large export through a short-idle-timeout proxy completes (streaming).
