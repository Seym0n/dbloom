# SPEC 01 — Configuration Subsystem (LegacyAdmin 5.2.3)

Source of truth: `legacy-release` (legacy tree, read-only).
All citations use paths relative to that root.

## 1. Configuration loading and precedence

- FR-CFG-001 (corrected in review wave 1) — The system shall load configuration in a fixed, layered order: (1) built-in defaults from `new Settings([])` (the `Servers` key is removed from the defaults and the first server's defaults are kept separately as `defaultServer`), (2) the file named by the constant `CONFIG_FILE` (default `<root>/config.inc.php`), whose `$cfg` array is merged raw with `array_replace_recursive` and is NOT passed through the `Settings` coercion setters, (3) runtime facts from `checkSystem()` (see FR-CFG-077), and (4) user preferences, applied by `loadUserPreferences()` only after authentication and the database connection. The `settings` array is seeded with `is_setup=false`. Evidence: `libraries/classes/Config.php:113` (seed), `:310-321` (defaults; `unset($cfg['Servers'])` at :317), `:329-400` (file include and merge at :397), `:421-457` (preferences); sequencing in `libraries/classes/Common.php:117` (Config obtained from the DI container, service `config` with argument `CONFIG_FILE` at `libraries/services.php:21-24`), `:218-236` (connect/auth), `:289` (`loadUserPreferences()`). Verification (added in review wave 2): start with an empty `config.inc.php` and a config file setting only `$cfg['MaxRows']=50`; dump `$GLOBALS['cfg']` after `Common::run()`: `MaxRows`=50, every other key equals its `Settings` default, `Servers` contains key 1. A config value with a string for `MaxRows` is kept as string (no coercion).

- FR-CFG-002 (corrected in review wave 1) — The constructor shall run `load()`, then `checkSystem()`, then snapshot the complete resulting `settings` array (defaults + config file + runtime facts such as `PMA_IS_WINDOWS`, `max_upload_size`, `enable_upload`, `PMA_USR_*`, `PMA_IS_GD2`, `PMA_IS_IIS`, resolved `OBGzip`) into the public property `baseSettings` before user preferences are applied. `baseSettings` shall be the source for validator `value:` placeholders (`Validator::getValidators`, which resolves them with `Core::arrayRead`) and for `ConfigFile`/`PageSettings`/preference pages that need values not overridden by user preferences. Evidence: `libraries/classes/Config.php:111-123`; `libraries/classes/Config/Validator.php:89-98`; consumers `libraries/classes/Controllers/Preferences/ManageController.php:73`, `libraries/classes/Config/PageSettings.php:77`.

- FR-CFG-003 — The system shall construct the config object with an optional source path; when a source is supplied it shall be trimmed and stored (`setSource`), checked for existence/readability, and only then included. Evidence: `libraries/classes/Config.php:111-123`, `libraries/classes/Config.php:598-601`, `libraries/classes/Config.php:606-646`.

- FR-CFG-004 — The system shall evaluate the configuration file as a PHP include inside output buffering (`ob_start()`/`ob_end_clean()`), with error reporting temporarily disabled when available, and shall suppress any output the file produces. Evidence: `libraries/classes/Config.php:344-369`.

- FR-CFG-005 (corrected in review wave 1) — The system shall silently discard (not report) configuration keys of `$cfg` read from the config file whose top-level key string contains `/`, because flattened paths make `$cfg['Export/method']` ambiguous versus `$cfg['Export']['method']`. Evidence: `libraries/classes/Config.php:378-395` (`array_filter` with `ARRAY_FILTER_USE_KEY` and `str_contains($key, '/')`). Verification (added in review wave 2): in `config.inc.php` set `$cfg['Export/method']='x'` and `$cfg['Export']['method']='quick'`; after load the first is absent from `settings` and the second is applied; no error or message is produced.

- FR-CFG-006 — The system shall record the modification time of the loaded configuration file (`sourceMtime`) when the include succeeds and reset it to `0` when the source does not exist or is unreadable; the mtime shall be used to invalidate the per-server user-preferences session cache. Evidence: `libraries/classes/Config.php:371-376`, `libraries/classes/Config.php:613-617`, cache invalidation at `libraries/classes/Config.php:431-443`.

- FR-CFG-007 — While the configuration file is being included, the system shall set a global `$isConfigLoading = true` guard, and a registered shutdown fatal-error handler shall convert a fatal error occurring during that window into a localized fatal error message including the relative file path and line. Evidence: `libraries/classes/Config.php:356-364`, `libraries/classes/Config.php:1026-1047`, registration in `libraries/classes/Common.php:107-109`.

- FR-CFG-008 — The system shall, when a configuration file cannot be read (e.g. unreadable on CIFS shares where `is_readable` may lie), perform a manual 1-byte `fopen/fread` readability probe and emit a fatal error "Existing configuration file (%s) is not readable." if unavailable. Evidence: `libraries/classes/Config.php:619-643`.

- FR-CFG-009 (corrected in review wave 1) — `Config::load()` shall return `false` (leaving pure defaults) only when no source path is set, the file does not exist, or it is unreadable. If the include itself fails (a `Throwable` is caught, or the include result is `false`), `errorConfigFile` shall be set to true, the partially produced `$cfg` is still merged, and `load()` returns `true`. When `errorConfigFile` is true, `checkErrors()` (called from `Common::run` after the language is activated) shall trigger the localized message "Failed to read configuration file!" plus a syntax-error hint and an embedded `[conferr]` iframe (`show_config_errors.php`), with severity `E_USER_ERROR` on PHP < 8.4 and `E_USER_WARNING` on PHP >= 8.4. Evidence: `libraries/classes/Config.php:339-341, 357-376, 682-694`; `libraries/classes/Common.php:172-173`; `libraries/classes/Sanitize.php:200`. Verification (added in review wave 2): put a PHP syntax error in `config.inc.php`: the page shows the localized "Failed to read configuration file!" message with the `[conferr]` iframe, defaults are in effect and `Config::load()` returns true; delete the file: no error and `load()` returns false.

- FR-CFG-010 — The system shall resolve the configuration file path from `libraries/vendor_config.php` (`$vendorConfig['configFile']`) captured as the constant `CONFIG_FILE`, alongside related deployment constants (`TEMP_DIR`, `CUSTOM_HEADER_FILE`, `CUSTOM_FOOTER_FILE`, `VERSION_CHECK_DEFAULT`, `CACHE_DIR`). Evidence: `libraries/constants.php:9-41`.

- FR-CFG-011 — The system shall verify configuration-file permissions after loading: if `CheckConfigurationPermissions` is enabled, the file exists, the world-writable bit (bit 2) is set, and the platform is not Windows (or not detected as such), it shall abort with a fatal "Wrong permissions on configuration file, should not be world writable!" and reset `sourceMtime` to 0. Evidence: `libraries/classes/Config.php:652-676`. Verification (added in review wave 2): on Linux `chmod 666 config.inc.php` with `CheckConfigurationPermissions=true`: request aborts with "Wrong permissions on configuration file, should not be world writable!"; with `chmod 644` or with the directive false the request proceeds; on Windows never aborts.

- FR-CFG-012 (corrected in review wave 1) — The system shall merge applied user preferences into both `$this->settings` and the global `$GLOBALS['cfg']` with `array_replace_recursive`, caching per server the session entries `$_SESSION['cache']['server_<n>']['userprefs']`, `userprefs_mtime`, `userprefs_type` and `config_mtime`; when `$isMinimumCommon` is set (setup, import-status) the DB is not queried and only an existing cache is applied. If the server is 0 or no cache exists, `user_preferences` is set to false and nothing is merged. Evidence: `libraries/classes/Config.php:421-457`.

- FR-CFG-013 — User-preference persistence shall be tiered: when a config-storage `userconfig` table is available the type is `db`, otherwise preferences fall back to session storage (`$_SESSION['userconfig']`); the active type and mtime are exposed as `user_preferences` and `user_preferences_mtime` runtime settings. Evidence: `libraries/classes/UserPreferences.php:76-117`, `libraries/classes/Config.php:444-453`.

- FR-CFG-014 — A single user-preference option shall be settable at runtime via `setUserValue`, which (a) writes to persistent preferences when `user_preferences` is active, (b) additionally writes a cookie when `user_preferences` is not `db` and a cookie name is supplied, and (c) updates both `$GLOBALS['cfg']` and `$this->settings` immediately. Values equal to the default shall be removed from persistent storage (`persistOption` semantics). Evidence: `libraries/classes/Config.php:535-566`, `libraries/classes/UserPreferences.php:254-268`.

- FR-CFG-015 — When reading a user value (`getUserValue`), the system shall prefer the persistent value and delete any lingering cookie; cookies are only consulted when persistent prefs are not `db`. Evidence: `libraries/classes/Config.php:576-591`.

- FR-CFG-016 — The system shall include `ThemeDefault`, `lang`, `Server/hide_db`, `Server/only_db` and `2fa` in the allow-list of writable user-preference paths, and shall apply the loaded preferences filtered by (allow-list ∩ ¬`UserprefsDisallow`). Evidence: `libraries/classes/UserPreferences.php:63-64, 221-241`.

- FR-CFG-017 — The system shall automatically reconcile theme and language preferences: when the theme cookie differs from the persisted `ThemeDefault` the system shall persist the current theme; when no cookie exists the default from preferences shall be activated and set as a cookie — analogously for language (`pma_lang`). Evidence: `libraries/classes/Config.php:467-514`.

- FR-CFG-018 — The system shall apply `DefaultConnectionCollation` to the active DB connection after preferences load, when non-empty and changed. Evidence: `libraries/classes/Config.php:405-415`, `libraries/classes/Config.php:516-517`.

- FR-CFG-019 — The system shall expose `getLoginCookieValidityFromCache`, which pulls `LoginCookieValidity` from the per-server preferences cache before it would be overridden by a later `loadUserPreferences()`, when `$cfg['Server']` is populated. Evidence: `libraries/classes/Config.php:1365-1378`, called from `libraries/classes/Common.php:222-223`.

- CON-CFG-020 (corrected in review wave 1) — Server selection (`selectServer`) shall read the request parameter `server`; a numeric value is used as index. A non-numeric value is matched against every configured server by `host` (loose equality), by `verbose` (exact or case-insensitive) or by `md5()` of the lower-cased `verbose` equal to the lower-cased request value; the first match wins and an unmatched string becomes 0. A numeric index is accepted only if `Servers[index]` is non-empty; otherwise `ServerDefault` (default 1) is used if that server exists; otherwise the server is 0, `Server` is set to an empty array and authentication is skipped (the welcome page still renders). Evidence: `libraries/classes/Config.php:1144-1195`, `libraries/classes/Config/Settings.php:1962-1971`. Verification (added in review wave 2): with servers 1 (verbose `Prod`) and 2 (host `db2`): `?server=2` selects 2; `?server=db2` and `?server=prod` (case-insensitive) select the respective servers; `?server=9` falls back to `ServerDefault`; with `ServerDefault=0` and an invalid index `$cfg['Server']` is empty and the welcome page renders without a login form.

- FR-CFG-021 (corrected in review wave 1) — After merging, `checkServers()` shall normalize the `Servers` array: if `Servers` is unset or empty it shall become `[1 => defaultServer]`; otherwise every entry is merged over `defaultServer` with `array_merge`; a server index that is not an integer >= 1 shall trigger the localized error "Invalid server index: %s" (`E_USER_ERROR` on PHP < 8.4, `E_USER_WARNING` on PHP >= 8.4) but is still kept; a server with both empty `host` and empty `verbose` shall get the localized verbose label "Server %d". Evidence: `libraries/classes/Config.php:1200-1237`. Verification (added in review wave 2): configure `$cfg['Servers'][0]` and `[2]`: error "Invalid server index: 0" is raised and index 0 is still kept; configure `Servers[3]` with empty host and verbose: its verbose label is "Server 3"; with no `Servers` at all `Servers` equals `[1 => defaults]`.

## 2. Accepted directives: types, defaults, constraints

- DATA-CFG-022 (corrected in review wave 1) — The system shall define every accepted directive and its default in the final, `@psalm-immutable` class `Settings` (`libraries/classes/Config/Settings.php`): public properties, each initialized by a dedicated private setter that falls back to the default when the input is unset or of a disallowed value, and a `toArray()` that also expands `Servers` into arrays. In 5.2.3 `Settings` is only ever instantiated with an empty array (`Config::loadDefaults`, `ConfigFile::__construct`), so the coercion/whitelisting is effectively a definition of defaults; values read from `config.inc.php` or user preferences are NOT coerced or whitelisted by it. Evidence: `libraries/classes/Config/Settings.php:37-45, 1577-1791`; `libraries/classes/Config.php:312`; `libraries/classes/Config/ConfigFile.php:93` (the only two `new Settings(` call sites in `libraries/` and `setup/`).

- DATA-CFG-023 (corrected in review wave 1) — Server defaults shall be defined per server in `Settings\Server` (indexed from 1; constructor at `Server.php:515`): `host='localhost'`, `port=''` (string), `socket=''`, `ssl=false`, `ssl_verify=true`, other `ssl_*` and `control*` strings `''`, `compress=false`, `auth_type='cookie'`, `user='root'`, `password=''`, `auth_http_realm=''`, `only_db=''`, `hide_db=''`, `verbose=''`, `pmadb=''`, `AllowRoot=true`, `AllowNoPassword=false`, `AllowDeny={order:'', rules:[]}`, `MaxTableUiprefs=100` (values < 1 revert to 100), `DisableIS=false`, `SessionTimeZone=''`, `hide_connection_errors=false`, `tracking_*` options, and every storage table name defaulting to the empty string. Evidence: `libraries/classes/Config/Settings/Server.php:515-576, 581-700, 763-770, 787-799, 1238-1248, 1265-1312, 1390-1397`.

- CON-CFG-024 (corrected in review wave 1) — `auth_type` shall be one of `config|http|signon|cookie` (any other value in the defaults-builder falls back to `cookie`) and `AllowDeny/order` one of `''|deny,allow|allow,deny|explicit` (otherwise `''`). These whitelists are enforced by `Settings\Server` only for default construction; for values supplied in `config.inc.php` the effective constraint is the select-list in `libraries/config.values.php:21-35` applied by setup forms (FR-CFG-036) and the `validateServer` check (FR-CFG-042). Evidence: `libraries/classes/Config/Settings/Server.php:763-770, 1292-1312`; `libraries/config.values.php:21-35`.

- DATA-CFG-025 (corrected in review wave 1) — Storage (pmadb) table-name settings (`bookmarktable`, `relation`, `table_info`, `table_coords`, `pdf_pages`, `column_info`, `history`, `recent`, `favorite`, `table_uiprefs`, `tracking`, `userconfig`, `users`, `usergroups`, `navigationhiding`, `savedsearches`, `central_columns`, `designer_settings`, `export_templates`) shall accept the boolean `false` (feature explicitly disabled) or any value cast to string; when unset the default is `''` (feature not configured, eligible for zero-conf fill-in). Evidence: `libraries/classes/Config/Settings/Server.php:952-1231` (e.g. `setBookmarktable` at 966-973); `libraries/classes/ConfigStorage/Relation.php:1636-1639` (`=== false` skips the feature).

- DATA-CFG-026 (corrected in review wave 1) — `Servers/n/SignonCookieParams` shall have the default shape `{lifetime:0, path:'/', domain:'', secure:false, httponly:false}` with optional `samesite`; `lifetime` is accepted only if (int) >= 1, `samesite` only if `Lax` or `Strict`, other entries are cast to string/bool and unknown entries dropped (default-construction only, see DATA-CFG-022). Evidence: `libraries/classes/Config/Settings/Server.php:828-864`.

- CON-CFG-027 (corrected in review wave 1) — Enumerated settings shall be constrained by allowed-value lists in `libraries/config.values.php` (used by setup/preferences forms and `FormDisplay::validateSelect`): e.g. `MaxRows` in {25,50,100,250,500}, `Order` in {ASC,DESC,SMART}, `OBGzip` in {auto,true,false}, `RecodingEngine` in {auto,iconv,recode,mb,none}, `ProtectBinary` in {false,'blob','noblob','all'}, `NavigationLogoLinkWindow` in {main,new}, `CharEditing` in {input,textarea}, `TabsMode`/`ActionLinksMode`/`TableNavigationLinksMode` in {icons,text,both}, `GridEditing` in {click,double-click,disabled}, `RelationalDisplay` in {K,D}, `InitialSlidersState` in {open,closed,disabled}, `SendErrorReports` in {ask,always,never}, `DefaultForeignKeyChecks` in {default,enable,disable}, `PDFDefaultPageSize` in {A3,A4,A5,letter,legal}, `FirstDayOfCalendar` in {1..7}, `Servers/1/only_db` of type `array`, `Servers/1/port` of type `integer`, `MemoryLimit`/`NavigationTreeDbSeparator`/`NavigationTreeTableSeparator` of type `short_string`, `NavigationWidth` of type `integer`; plus enumerations for `Import/*`, `Export/*` and `Console/{Mode,OrderBy,Order}`. (Corrects the earlier spelling `OBGZip`; the directive is `OBGzip`.) Evidence: `libraries/config.values.php:21-369`.

- DATA-CFG-028 (corrected in review wave 1) — `libraries/config.values.php` shall additionally provide `_overrides` (full-path default overrides applied by `ConfigFile::__construct` onto its copy of the defaults; empty in the shipped file), `_validators` (field or form id -> validator name or list of `[name, args...]`) and `_userValidators` (extra validators appended only outside setup, with `value:<path>` arguments resolved from `baseSettings`). Evidence: `libraries/config.values.php:371-483`; `libraries/classes/Config/ConfigFile.php:96-104`; `libraries/classes/Config/Validator.php:64-107`.

- DATA-CFG-029 — The system shall keep a module of human-readable names/descriptions/comments for options (`Descriptions`), used as form labels and messages (e.g. `ZeroConf_name`, `ZeroConf_desc`). Evidence: `libraries/classes/Config/Descriptions.php` (e.g. lines 547, 976 for ZeroConf).

## 3. ConfigFile editing model (setup + per-page settings)

- FR-CFG-030 — The system shall implement an editable configuration model (`ConfigFile`) whose working data is stored in the session under key `ConfigFile{server}` (id = `ConfigFile` + current server global); it shall support reset (`resetConfigData`) and full replacement (`setConfigData`). Evidence: `libraries/classes/Config/ConfigFile.php:83-114, 174-187`.

- FR-CFG-031 — `ConfigFile::set()` shall use canonical paths (any `Servers/<n>/` prefix normalized to `Servers/1/`), honor a set-allowed-keys filter when present, auto-remove values equal to the default (in setup: also when both value and default are empty; outside setup: only when the value equals both default and the base `config.inc.php` value), and always persist keys registered through `setPersistKeys`. Evidence: `libraries/classes/Config/ConfigFile.php:196-237`, `getCanonicalPath` at 347-350.

- FR-CFG-032 — The system shall persist a defined set of keys even at default value in setup (persist keys): `DefaultLang, ServerDefault, UploadDir, SaveDir, Servers/1/verbose, Servers/1/host, Servers/1/port, Servers/1/socket, Servers/1/auth_type, Servers/1/user, Servers/1/password`. Evidence: `setup/lib/common.inc.php:46-61`.

- FR-CFG-033 — The system shall support per-page settings modal forms built from `Config\Forms\Page\*Form` groups (Browse, DbStructure, Edit, Export, Import, Navi, Sql, TableStructure), processed through a fresh `ConfigFile` initialized from `baseSettings`, saved into user preferences, and reloaded by redirect; hidden when print view is requested. Evidence: `libraries/classes/Config/PageSettings.php:58-117`.

- FR-CFG-034 — `ConfigFile` shall provide server bookkeeping: server count, server list (from session), DSN rendering that never leaks more than a masked password segment (`:***`) when auth is `config` and a password is set, server name resolution preferring `verbose` then `host` then `localhost`, and `removeServer()` which compacts indexes downward and drops `ServerDefault` when it points at the last server. Evidence: `libraries/classes/Config/ConfigFile.php:370-471`.

## 4. Form display, processing, validation and sanitization

- FR-CFG-035 (corrected in review wave 1) — Form rendering (`FormDisplay`) shall derive each field's type in `Form::readTypes()`: `group` for `:group:` pseudo-fields; for other fields `select` when the `config.values.php` entry is an array, the entry itself (`string`, `short_string`, `integer`, `array`, ...) when it is a type name, else `gettype()` of the default value (`boolean`, `integer`, `double`, `string`, `array`). Fields shall be rendered per type, show the default value when unset, mark "value is default", and carry documentation links (not for `Import*`/`Export*` paths) and user-preference allow annotations. For `RecodingEngine` and `ZipDump/GZipDump/BZipDump` the form shall append a warning comment when the required PHP extension/function (`iconv`, `recode_string`, `zip_open`, `gzcompress`, `gzopen`, `gzencode`, `bzopen`, `bzcompress`) is missing. Evidence: `libraries/classes/Config/Form.php:260-278`; `libraries/classes/Config/FormDisplay.php:337-379, 742-754, 791-870`.

- FR-CFG-036 (corrected in review wave 1) — Form save (`FormDisplay::save`) shall: skip `group` pseudo-fields; treat a missing POST value as the error "Missing data for %s" for every type except `boolean` (which becomes false: unchecked-checkbox semantics); cast values per type (`double` -> float, `boolean|integer` -> `settype` unless the value is the empty string, `string|short_string` -> request-string, `array` -> split on newlines with empty entries dropped); validate `select` values against the allowed list (error "Incorrect value!"). When any of these save-time errors exist and partial save is disabled (`process(false)`, as used by setup, page settings and preference pages), nothing shall be written. Semantic validation (FR-CFG-040) runs after the write and never blocks the save; it only populates the error list reported by `hasErrors()`. Evidence: `libraries/classes/Config/FormDisplay.php:566-725`. Verification (added in review wave 2): post a Features form with an omitted text field: error "Missing data for <field>" and nothing saved; omit a checkbox: saved as false; post a `select` field with a value outside `config.values.php`: "Incorrect value!"; post a non-numeric `MaxRows`: it is saved (semantic validation never blocks the save) and reported by `hasErrors()`.

- FR-CFG-037 — On save, a new server (form index 0) shall be written under a newly allocated index (`getServerCount()+1`), replacing `Servers/1/` work paths with the new index. Evidence: `libraries/classes/Config/FormDisplay.php:585-588, 669-677`.

- FR-CFG-038 — The `TrustedProxies` field shall be transformed before saving from lines of `IP: HTTP header` into a map `{IP: header}`, preserving unparseable lines under synthetic negative keys `-{n}`. Evidence: `libraries/classes/Config/FormDisplay.php:689-709`.

- FR-CFG-039 — In setup, the system shall record per-field "userprefs allow" decisions (`<key>-userprefs-allow` POST flag) into `UserprefsDisallow` on the ConfigFile. Evidence: `libraries/classes/Config/FormDisplay.php:615-622, 714-719`.

- FR-CFG-040 (corrected in review wave 1) — Validation shall be declarative: validators registered in `_validators`/`_userValidators` are invoked as `LegacyAdmin\Config\Validator::<name>(canonicalFieldId, &values, ...extraArgs)`; the validator list is computed once per request (static cache); field ids are canonicalized (`Servers/<n>/` -> `Servers/1/`; `-` -> `/` for POST-sourced values). `Validator::validate` shall return `false` when none of the requested ids has a validator, `true` when validators ran without errors, otherwise an array `path => string[]` of errors passed through `Sanitize::sanitizeMessage`; when the source is not POST, empty error entries are omitted. Evidence: `libraries/classes/Config/Validator.php:64-202`.

- FR-CFG-041 (corrected in review wave 1) — Built-in validators shall be: `validatePositiveNumber` (integer > 0, <= PHP_INT_MAX, "Not a positive number!"), `validateNonNegativeNumber` (integer >= 0, "Not a non-negative number!"), `validatePortNumber` (integer 1..65535, "Not a valid port number!"), `validateByRegex` (pattern must match, "Incorrect value!"), `validateRegex` (value must be a compilable PCRE fragment when wrapped in `/.../`), `validateUpperBound` (value <= bound, "Value must be less than or equal to %s!"), `validateTrustedProxies` (each line `IP: header`, IPv4 or IPv6 via `filter_var`) plus `validateServer` / `validatePMAStorage`. An empty value always passes the numeric validators. Assignments in `_validators`: non-negative: `Console/Height`, `ExecTimeLimit`, `Import/skip_queries`, `NumRecentTables`, `NumFavoriteTables`, `LoginCookieStore`, `MinSizeForInputField`, `NavigationWidth`, `RepeatCells`; positive: `CharTextareaCols/Rows`, `TextareaCols/Rows`, `Export/sql_max_query_size`, `FirstLevelNavigationItems`, `ForeignKeyMaxLimit`, `InsertRows`, `LimitChars`, `LoginCookieValidity`, `MaxDbList`, `MaxTableList`, `MaxNavigationItems`, `MaxCharactersInDisplayedSQL`, `MaxRows`, `MaxSizeForInputField`, `NavigationTreeDisplayItemFilterMinimum`, `NavigationTreeTableLevel`, `QueryHistoryMax`; regex: `MemoryLimit` (`/^(-1|(\d+(?:[kmg])?))$/i`), `Import/csv_enclosed` and `Import/ldi_enclosed` (`/^.?$/`), `Import/csv_escaped|csv_terminated|ldi_escaped|ldi_terminated` (`/^.$/`), `Servers/1/hide_db` (`validateRegex`); `Servers/1/port` (port); `TrustedProxies`; `Server` and `Server_pmadb` (connection tests). User-preference-only upper bounds cap `MaxDbList`, `MaxTableList`, `QueryHistoryMax` at the `baseSettings` value. Evidence: `libraries/config.values.php:382-483`; `libraries/classes/Config/Validator.php:388-613`. Verification (added in review wave 2): call each validator: `validatePositiveNumber('0')` -> "Not a positive number!", `'5'` and `''` pass; `validatePortNumber('65536')` -> "Not a valid port number!"; `validateByRegex` with `MemoryLimit` `-1`, `128M` pass and `12X` fails; `validateTrustedProxies` accepts `1.2.3.4: X-Forwarded-For` and `::1: X-Real-IP`, rejects `1.2.3: foo`.

- FR-CFG-042 — Server validator (`validateServer`) shall enforce: non-empty `auth_type`; non-empty `user` when auth is `config`; non-empty `SignonSession` and `SignonURL` when auth is `signon`; and, when auth is `config`, a live connection test via `mysqli_connect` (host sanitized through `Core::sanitizeMySQLHost`, sockets/ports normalized, `mysqli_report(MYSQLI_REPORT_OFF)`, errors reported as "Could not connect to the database server!" plus the last PHP error). Connection testing shall be disabled on the demo server (`DBG.demo`). Evidence: `libraries/classes/Config/Validator.php:216-323`.

- FR-CFG-043 — Storage validator (`validatePMAStorage`) shall require non-empty `controluser` and `controlpass` whenever `pmadb` is set, then run the same live connection test with the control credentials against the main server host/port/socket. Evidence: `libraries/classes/Config/Validator.php:335-378`.

- FR-CFG-044 (corrected in review wave 1) — The validation callback endpoint (`setup/validate.php`) shall send a JSON content-type header, accept POST `id` (comma-separated validator ids) and `values` (a JSON object, decoded to an array), and output: an empty string when validation succeeded (`true`); a JSON-encoded error map when it failed; and a JSON-encoded localized string "Wrong data or no validation for %s" when no validator matches. A `values` payload that is not a JSON object shall abort with the fatal error "Wrong data". Evidence: `setup/validate.php:24-43`, `Core::headerJSON()`. ### 10.3 How the storage database is found

- FR-CFG-112 (added in review wave 3) — The storage database shall be resolved in this order on every request when `ZeroConf` is true and a server is selected (`Common.php:296-302` -> `postConnectControl` -> `Relation::initRelationParamsCache`, `Relation.php:1813-1832`): (1) `Servers/n/pmadb` if non-empty, else the literal `legacyadmin`, probed with `fixPmaTables($name, false)` (no creation); (2) if that probe adopted no database (`$cfg['Server']['pmadb']` still empty), the database of the current request, `$GLOBALS['db']` (empty at server level), probed the same way. A probe adopts a database (sets `$cfg['Server']['pmadb']` to it for the request, fills empty table-name keys with the `la_*` defaults, unsets and refills `$_SESSION['relation'][$server]`) as soon as at least one of the 19 tables (or its configured replacement name) exists there; it does not check that all tables exist or that the account can read them (access is checked afterwards per table, `checkTableAccess`, FR-CFG-068). The shortcut name `getConfigurationStorageDbName()` (configured name, else `legacyadmin`) is used only by the check-relations page (`Relation.php:1799-1807`). With `ZeroConf=false` the lookup is skipped and only explicit keys count. Persistence of a discovered database while the user browses other databases: the discovery result is kept in `$_SESSION['relation'][<server index>]` (key = server number, not host; reused while `version` equals `Version::VERSION`, `Relation.php:60-87`). On a later request in another database that contains no `la_*` table the probe adopts nothing and leaves that cache untouched, so the previously discovered database stays in use for the session; the per-request value `$cfg['Server']['pmadb']` is however empty again in such a request, so code that reads it directly (`DatabasesController.php:274` `is_pmadb` flag, `DestroyController.php:69` drop guard, `HomeController.php:217`) does not see the discovered database. The cache is replaced when the probe finds tables elsewhere (the `legacyadmin` database wins over the current database, because it is probed first), when `fixPmaTables` or `createPmaDatabase` succeed, when `UserPreferences::save` finds the storage inaccessible (FR-CFG-070), and implicitly with every new login/session. The probe also runs earlier than the line above suggests: the `TwoFactor` constructor calls `initRelationParamsCache()` itself (`TwoFactor.php:63`) during `checkTwoFactor()` right after the connection is opened (`Common.php:236-240`), i.e. before `loadUserPreferences()` (`:289`), so on the first request the preferences already see the discovered storage; `$GLOBALS['db']` is set from the request parameter `db` at `Common.php:142`, before any connection. Evidence: as cited, plus `libraries/classes/ConfigStorage/Relation.php:262-283` (an unresolved cache miss with empty `pmadb` sets `$cfg['Server']['pmadb'] = false` and caches an all-false result). Verification: with `ZeroConf=true`, empty `pmadb` and tables only in database `foo`: select `foo`, `$_SESSION['relation'][1]['db']` becomes `foo`; select `bar` (no tables): the entry still says `foo` and the preferences remain type `db`; create database `legacyadmin` with tables: after the next request the entry says `legacyadmin`; log in again without selecting `foo`: storage is gone. This refines CPT-CFG-071. Related conflict: CF-007.

### 10.4 Connection model

- INT-CFG-113 (added in review wave 3) — The configuration storage shall always be accessed through a separate "control" connection, distinct from the connection of the logged-in user, so that storage queries are not affected by locks held on the main connection (comment at `Common.php:626-629`). `Common::connectToDatabaseServer`: (a) if `Servers/n/controluser` is not the empty string, a control connection is opened with `controluser`/`controlpass`, host = `controlhost` if non-empty else the login host, port = `controlport` if non-empty, other connection options (socket, SSL, compress) shared only when the control host equals the login host (INT-CFG-089, `Config.php:1255-1300`); (b) the user connection is opened with the login credentials (failure -> `mysql-denied` login failure); (c) if there was no `controluser`, or the control connection failed (`$controlLink` false), a second connection is opened with the login user's own credentials and used as the control connection (`connect(CONNECT_USER, null, CONNECT_CONTROL)`). Consequences: with a control user, all storage rows are written under that account's privileges while the row owner (`username`) is still the login name; without it, the login user needs `SELECT`/`INSERT`/`UPDATE`/`DELETE` (and for creation `CREATE`) on the storage database, and every user must be granted separately; a control connection that fails to open silently falls back to (c) (the `connect` result is only tested, no error is raised). Evidence: `libraries/classes/Common.php:602-631`; `libraries/classes/Config.php:1255-1300`. Verification: set `controluser` to a valid account and observe two connections in `SHOW PROCESSLIST` (control user + login user); remove `controluser`: two connections both with the login user; set a wrong `controlpass`: no error, two connections with the login user. Related conflict: CF-001.

- SEC-CFG-114 (added in review wave 3) — `AllowArbitraryServer` shall default to `false` (`Settings.php:2383-2389`: unset -> false; `Settings.php:391`, mirrored in `config.default.php`; the shipped `config.sample.inc.php` does not mention it). This verifies the earlier statement in CF-006, which was marked "not re-verified". When it is true, the cookie-auth login page (`templates/login/form.twig:62-72`, flag `is_arbitrary_server_allowed` at `AuthenticationCookie.php:180`) shows an additional free-text field `pma_servername` ("You can enter hostname/IP address and port separated by space."), pre-filled with the default server host, and the server `<select>` clears it on change (`form.twig:99`). On submit the typed value is optionally checked against `ArbitraryServerRegexp` (error "You are not allowed to log in to this MySQL server!"; checked against the first part when two parts are given) (`AuthenticationCookie.php:305-318`), stored in the encrypted login cookie (`:538-540`) and, after authentication, written into `$cfg['Server']['host']` (and `port` when a second part was given) (`:425-440`). Because storage resolution, `getConnectionParams` and the control connection all read `$cfg['Server']`, they run against the typed server: the storage is looked up on that server (10.3), and with `controluser` configured and `controlhost` empty the configured `controluser`/`controlpass` are sent to the host the user typed. `controlhost` set explicitly avoids this for the host but the credentials are still those of the configured control account. The relation cache is keyed by server number only (`$_SESSION['relation'][$server]`), which is safe only because one login session binds one typed host. Setup warns when the option is enabled (SEC-CFG-059). Evidence: as cited. Verification: with the option off the login form has no `pma_servername` field and the posted value is ignored; with it on and `ArbitraryServerRegexp='/^db\\d+$/'`, typing `evil` is refused; typing `db1` makes `SHOW PROCESSLIST` on `db1` show the control user (if configured) and the login user. Related conflicts: CF-006, CF-001.
