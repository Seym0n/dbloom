# 00 — System Overview & Cross-Cutting Requirements

Legacy system under analysis: **LegacyAdmin 5.2.3** (`legacy-release`), 2,613 files in the release tree (2,570 excluding the source's own `doc/`), 955 `*.php` files of which 612 are under `libraries/classes/`, 77 first-party JS files under `js/src/`, 4 bundled themes (`themes/bootstrap|metro|original|pmahomme`), 24 template sub-folders under `templates/` (corrected in review wave 1; counts re-measured from the tree).

## 1. System purpose

LegacyAdmin is a PHP web application for administering MySQL and MariaDB servers through a browser: browsing and editing data, running SQL, managing users/privileges, importing and exporting databases, and administering server state (processes, variables, replication). It may run with no persistent state of its own ("zero-conf") or install its own *configuration storage* schema (`la_*` tables, `sql/create_tables.sql`, 19 tables) for bookmarks, history, UI preferences, and more.

## 2. Actors / stakeholders

| Actor | Stake in the system |
|---|---|
| **End user / DBA** | Full database administration through the browser; per-user preferences, 2FA, saved SQL. |
| **Control user** | Dedicated MySQL account (`$cfg['Server']['controluser']`) that owns and serves the `la_*` configuration-storage tables to all users. |
| **Setup administrator** | Person running the `setup/` wizard to generate `config.inc.php`. |
| **Application (signed-on user)** | Another PHP app that injects credentials via the `signon` auth method. |
| **Developer / packager** | Builds (Yarn/Composer), packages for OS distributions. |
| **MySQL/MariaDB server** | External system; feature set differences are explicitly version-branched throughout the code. |

Cross-cutting requirements for all actors as **CC** (cross-cutting). IDs here take the form `TYPE-CC-NNN`:

- **NFR-CC-001** — The system shall run on PHP `^7.2.5 || ^8.0` and, on PHP older than 7.2.5, shall terminate with the message "PHP 7.2.5+ is required." plus the installed version, before loading any other file (`index.php:14-16`, `composer.json:56`). (corrected in review wave 1: added Composer constraint and exact behaviour)
- **SEC-CC-002** — Includable library files shall be non-executable when requested directly: `libraries/constants.php`, `libraries/config.values.php`, `libraries/routes.php`, `libraries/vendor_config.php` and `setup/lib/common.inc.php` shall `exit` if the constant `LEGACYADMIN` (defined only by entry scripts, e.g. `index.php:19`) is not defined (`libraries/constants.php:5-7`, `libraries/config.values.php:9`, `libraries/routes.php:40`, `libraries/vendor_config.php:12`, `setup/lib/common.inc.php:13`). Entry scripts define `ROOT_PATH` if absent (`index.php:8-12`). (corrected in review wave 1: original cited index.php as the guard)
- **NFR-CC-003** — The system shall be deployable without a Node toolchain at the web host once compiled assets exist: CSS/JS are produced by `yarn run build` (sass, postcss, rtlcss, babel `js/src` -> `js/dist`) and PHP dependencies by Composer (`package.json:51-60`, `composer.json`). The analysed source tree contains no `js/dist`, so a build or a prebuilt release archive is a precondition for running the UI. (corrected in review wave 1: removed dependency on the ignored doc/ folder)
- **INT-CC-004** — The system shall support MySQL and MariaDB servers with version >= 5.5.0 (`$cfg['MysqlMinVersion'] = ['internal' => 50500, 'human' => '5.5.0']`, `libraries/config.default.php:2982-2985`); after authentication, a server reporting a lower version shall abort with "You should upgrade to MySQL 5.5.0 or later." (`Common.php:245-253`). The server family is detected by `stripos($versionString, 'mariadb')` (`DatabaseInterface.php:2392`) and selects the SQL-parser context `MariaDb<ver>` or `MySql<ver>` (`DatabaseInterface.php:1157`); family-specific behaviour is specified in `02-server.md` (replication, password handling). (corrected in review wave 1: added limit, error behaviour, evidence)
- **UI-CC-005** — The system shall offer a translatable UI (gettext catalogs under `po/`, selected at runtime by `LanguageManager::getInstance()->selectLanguage()` then `activate()`, `Common.php:165-166`) and shall set `$GLOBALS['text_dir']` to `rtl` for right-to-left languages (`Language.php:166-189`); RTL stylesheets are generated by `css-rtl` (`package.json:57`). See `07-frontend.md` section 16. (corrected in review wave 1: ID type `I18N` is not a defined type, so I18N-CC-005 is renamed UI-CC-005; dangling reference to 06-plugins.md section 6.7 removed)
- **CON-CC-006** — The system shall remain GPL version 2: the repository ships the GPLv2 text in `LICENSE`, and package metadata declares `GPL-2.0-only` (`composer.json:15`) and `GPL-2.0` (`package.json:7`). (corrected in review wave 1: replaced doc/ evidence; the SPDX spelling differs between the two manifests)
- **NFR-CC-007** — User preferences shall be persisted in `la_userconfig` (column `config_data`, JSON) when the configuration-storage user-preferences feature is available (`type` = `db`); otherwise they shall be held only in `$_SESSION['userconfig']` (`type` = `session`) and are lost with the session (`UserPreferences.php:76-117`). Loaded preferences are cached per server in `$_SESSION['cache']['server_<n>']['userprefs']` (`Config.php:421-457`). Cookies are used only for individual options written through `Config::setUserValue` (see `01-configuration.md` FR-CFG-014). (corrected in review wave 1: the original claimed a cookie-or-table fallback) (corrected in review wave 2: this item restates **FR-CFG-013** and **FR-CFG-095** in `01-configuration.md`, which are authoritative for the details - columns, save/error behaviour, the `user_preferences` runtime settings; the ID NFR-CC-007 is kept as the cross-cutting summary and shall not be counted as a separate behaviour in a traceability matrix.)
- **SEC-CC-008** — For POST requests the system shall compare the submitted `token` with `$_SESSION[' PMA_token ']` using `hash_equals` (`Common.php:476-492`). If the token is missing or different, all request variables except `ajax_request` shall be removed (`Sanitize::removeRequestVars`, `Common.php:508-510`), and an AJAX POST shall be answered with "Error: Token mismatch" and terminated (`Common.php:275-282`). GET requests are not token-checked (`Common.php:483-485`). Logout via GET or with a mismatched token only redirects to `./index.php?route=/` (`Controllers/LogoutController.php:15-19`). (corrected in review wave 1: the original said requests "shall be refused"; non-AJAX requests are processed with parameters stripped)
- **SEC-CC-009** — Sessions shall be hardened at start-up: cookie-only (`session.use_only_cookies=1`), strict mode, HttpOnly, `session.use_trans_sid=0`, session-lifetime cookie (`cookie_lifetime=0`), `SameSite` from `$cfg['CookieSameSite']` (default `Strict`), the `Secure` flag set when the request is HTTPS, optional `SessionSavePath`; if `session_start()` fails or raises errors, execution shall stop with a fatal error (`Session.php:111-206`). (added in review wave 1)
- **SEC-CC-010** — The session shall be regenerated on login: `Session::secure()` calls `session_regenerate_id(true)`, `session_unset()` and generates a new 16-byte `PMA_token` and `HMAC_secret` (`Session.php:43-46,60-68`); it is invoked when credentials are submitted (`Plugins/Auth/AuthenticationCookie.php:326`) and before the login form is shown (`Plugins/AuthenticationPlugin.php:257`). (added in review wave 1)
- **NFR-CC-011** — At boot the system shall check PHP extensions: `mbstring` and `mysqlnd` (`mysqli_stmt_get_result`) produce a warning; `pcre`, `json`, `ctype` and `hash_hmac` are fatal when missing (`Core::warnMissingExtension(..., true)`) (`Common.php:308-355`); `composer.json:57-63` additionally requires `ext-hash`, `ext-iconv`, `ext-json`, `ext-mysqli`, `ext-openssl`, `ext-pcre`, `ext-xml`. If `ini_get`/`ini_set` are disabled the system shall report that LegacyAdmin requires them (`Common.php:549-580`). (added in review wave 1)
- **NFR-CC-012** — PHP runtime settings shall be normalised at boot: `default_charset=utf-8`, `mb_internal_encoding('utf-8')`, `precision=14`, and the default timezone re-set to its current value to avoid repeated E_WARNINGs (`Common.php:358-381`). (added in review wave 1)
- **DEP-CC-013** — The system shall open the control connection during boot as follows: if `$cfg['Server']['controluser'] !== ''` a `CONNECT_CONTROL` link is opened with that account (failure raises "Connection for controluser as defined in your configuration failed." and boot continues); otherwise a second connection with the user's own credentials is opened as the control link. A failed user connection shall call `showFailure('mysql-denied')` (`Common.php:602-632`, `DatabaseInterface.php:1953-2000`). (added in review wave 1)
- **DEP-CC-014** — Authentication outcomes shall be loggable: `Logging::logUser` sets Apache notes `userID`/`userStatus` when available, does not log successful logins unless `$cfg['AuthLogSuccess']` is true (default `false`), and writes to the destination from `$cfg['AuthLog']` (`auto` -> `syslog` if available, else PHP `error_log`; or `syslog` / `php` / a file) (`Logging.php:34-100`, `libraries/config.default.php:53`). (added in review wave 1)
- **NFR-CC-015** — Routing failures shall yield deterministic responses: unknown route -> HTTP 404 with "Error 404! The page <route> was not found." (route HTML-escaped); known route with wrong HTTP method -> HTTP 405 "Error 405! Request method not allowed." (`Routing.php:155-181`). The route cache `libraries/cache/routes.cache.php` (`CACHE_DIR` = `libraries/cache/`, `libraries/vendor_config.php:71`) shall be bypassed when `$cfg['environment'] === 'development'` (`Routing.php:45-50`). (added in review wave 1)
- **NFR-CC-016** — Import reading shall be bounded by memory: read-chunk limit = PHP `memory_limit` / 8, where an empty limit is treated as 2 MiB and `-1` as 10 MiB, and suffixes k/m/g are honoured (`Controllers/Import/ImportController.php`, memory-limit block before `$read_limit = $memory_limit / 8`). (added in review wave 1)

- **SEC-CC-017** — "Superuser" in LegacyAdmin means that the connected MySQL account can read the privilege table: `DatabaseInterface::isSuperUser()` runs `SELECT 1 FROM mysql.user LIMIT 1` and is true when this succeeds and returns a row; the result is cached in the session cache key `is_superuser`. It is **not** a check for the MySQL `SUPER` privilege. It is used, for example, to decide whether `DROP DATABASE` is allowed when `$cfg['AllowUserDropDatabase']` is false (`Sql::hasNoRightsToDropDatabase`, called at `Controllers/Sql/SqlController.php:155-159`) and by the server controllers (see `02-server.md` SEC-SRV-009, `05-security-auth.md` SEC-SAU-322 and `03-database-table.md` SEC-DTB-002). Together with `isGrantUser()` and `isCreateUser()` these are the only LegacyAdmin-side authorisation predicates; everything else relies on the privileges of the MySQL account. (`DatabaseInterface.php:1746-1766`) (added in review wave 2)
- **SEC-CC-018** — Cookie-auth credentials (user name, and the password when stored) shall be encrypted with libsodium `sodium_crypto_secretbox` (XSalsa20-Poly1305): 32-byte key, 24-byte random nonce per record, cookie value = base64(nonce || ciphertext); there is no AES/OpenSSL path. The key is `$cfg['blowfish_secret']` when it is at least 32 bytes (longer values are truncated to 32), otherwise a random per-session key (`$_SESSION['encryption_key']`), so the remembered user name cannot be decrypted in a new session; the name "blowfish" is historical. The optional URL-query encryption (`$cfg['URLQueryEncryption']`, default `false`) uses the same primitive in `Crypto/Crypto.php` with `URLQueryEncryptionSecretKey`. `composer.json` requires `paragonie/sodium_compat` (`:67`) and only suggests `ext-sodium` ("better encryption performance", `:100`), so the primitive is available without the PHP extension. Details: `05-security-auth.md` SEC-SAU-207 (cookie), FR-SAU-066 (URL query); `08-deployment-docs.md` SEC-DEP-052, FR-DEP-055. (`Plugins/Auth/AuthenticationCookie.php:588-653`, `Crypto/Crypto.php:21-60`) (added in review wave 2)
- **CON-CC-019** — `libraries/config.default.php` is a documentation/reference mirror of the defaults and is **not loaded at runtime**: the effective defaults come from `LegacyAdmin\Config\Settings` (`new Settings([])`, `Config.php:312`), and a unit test asserts that the mirror equals `Settings`. Statements in the SPEC files that cite `config.default.php` for a default cite the mirror; if the two ever differ, `Settings` is authoritative. Values from `config.inc.php` are merged without coercion by `Settings`. See `01-configuration.md` CON-CFG-106, CON-CFG-107 (mapping of every directive to its `Settings` setter), DATA-CFG-022 and FR-CFG-001. (added in review wave 2)
- **CPT-CC-020** — Platform and client baseline in one place: PHP `^7.2.5 || ^8.0` (`composer.json:56`; run-time gate `PHP_VERSION_ID < 70205` in `index.php:14`; NFR-CC-001); MySQL/MariaDB >= 5.5.0 (INT-CC-004); client libraries are pinned in `package.json` - Bootstrap **5.3.8** (`:19`), jQuery 3.7.1 (`:21`), jQuery UI 1.13.3 (`:24`), CodeMirror 5.65.10 (see `08-deployment-docs.md` DEP-102) - and the compiled assets are not part of the source tree (NFR-CC-003). Any statement of another minimum (for example "PHP 7.1", "PHP 7.2.0") or of "Bootstrap 5.0" in a SPEC file is wrong. (added in review wave 2)
- **INT-CC-021** — Availability of formats and backends is conditional, not universal (corrected statements, review wave 2): (a) the export format list is filtered by each plugin's `isAvailable()` (`Plugins.php:119-150`): **XML** export exists only when a database is selected (`ExportXml.php:551-557`), **PDF** export only when the TCPDF class and the `curl` extension are present (`ExportPdf.php:334-337`) - neither is "always available"; (b) the format called "CSV for MS Excel" (`ExportExcel extends ExportCsv`) produces CSV with Excel-oriented separators, **not XLSX**; there is no XLSX reader or writer; the spreadsheet formats are ODS (import and export) and ODT (export); (c) upload progress uses only the `progress` (PECL `uploadprogress`) or `noplugin` provider: the PHP `session.upload_progress` provider class `UploadSession` exists but its entry is commented out in `Import/Ajax.php:42-60`, so it is never selected and "session upload progress" does not work as a progress source; (d) `Plugins::getPlugin()` instantiates by name and does not check `isAvailable()`. Details: `04-io-formats.md` FR-IOX-001, FR-IOX-060; `06-plugins.md` FR-PLG-001, FR-PLG-005, DEP-PLG-003; views 9.4 and 9.20. (added in review wave 2)

## 4. Architectural facts grounding the specs

1. **Single entry routing.** `index.php` performs: PHP version check, autoloader (`AUTOLOAD_FILE`; fatal message if missing/unreadable, `index.php:27-36`), `Common::run()` boot, and route dispatch: `Routing::getDispatcher()` then `Routing::callControllerForRoute($request, $route, $dispatcher, $containerBuilder)` (`index.php:38-43`). `Routing` caches the compiled route table in `Routing::ROUTES_CACHE_FILE = CACHE_DIR . 'routes.cache.php'` (`Routing.php:36,122`). (corrected in review wave 1)
2. **Boot pipeline.** `Common::run()` executes in this order: container and error handler; `checkRequiredPhpExtensions` -> `configurePhpSettings` -> `cleanupPathInfo` (`Common.php:100-102`); load `config`; `Session::setUp` (`:123`); decrypt query params (`:126`); `setGotoAndBackGlobals` -> `checkTokenRequestParam` -> `setDatabaseAndTableFromRequest` (`:140-142`); language selection (`:165-166`); `checkPermissions`/`checkErrors`/`checkServerConfiguration`/`checkRequest` (`:172-176`); `checkServers`/`selectServer` (`:180-187`); theme init (`:196`); `DatabaseInterface::load()` (`:218`); `Plugins::getAuthPlugin()->authenticate()` (`:225-226`); `connectToDatabaseServer` (`:236`); `rememberCredentials` (`:238`); `checkTwoFactor` (`:240`); `Logging::logUser` (`:243`); minimum-version check (`:245`); AJAX token-mismatch exit (`:275`); `Profiling::check` (`:284`); `loadUserPreferences` (`:289`); `Tracker::enable` (`:294`); optional ZeroConf relation set-up (`:296`). User preferences are therefore loaded AFTER authentication and connection. (corrected in review wave 1: the original listed preferences before authentication)
3. **Data-access abstraction.** `DatabaseInterface implements DbalInterface` (`DatabaseInterface.php:78`) and is constructed with a `DbiExtension` (`:153`); the only bundled extension is `Dbal\DbiMysqli implements DbiExtension` (`DbiMysqli.php:41`), whose results are `Dbal\MysqliResult implements ResultInterface` (`MysqliResult.php:26`). Connection modes: `CONNECT_USER = 0x100`, `CONNECT_CONTROL = 0x101`, `CONNECT_AUXILIARY = 0x102` (`DatabaseInterface.php:100,104,110`). (corrected in review wave 1)
4. **Plugin families.** Export, import and schema plugins implement the `Plugins\Plugin` interface (`getName()`, `getProperties()`, static `isAvailable()`; `Plugins/Plugin.php:9-18`); transformations implement `TransformationsInterface`; upload-progress providers implement `UploadInterface`; authentication (`AuthenticationPlugin`) and two-factor (`TwoFactorPlugin`) plugins are base classes that do NOT implement `Plugin`; see `09-diagrams.md` section 9.4. Two-factor backends: `application` (TOTP only, no HOTP), `WebAuthn` (bundled `CustomServer` without signature verification, FR-SAU-059), `key` (U2F), `simple` (debug only) and the fallback `Invalid`; format and upload availability: INT-CC-021. (corrected in review wave 2) (corrected in review wave 1: the original said every plugin derives from "abstract plugin contracts")
5. **Presentation.** Twig templates under `templates/` (Twig cache in `tmp/twig` via `Config::getTempDir('twig')`, `Template.php:60`), 4 themes (`bootstrap`, `metro`, `original`, `pmahomme`), compiled assets under `js/dist/` and `themes/*/css/` generated by the build (`package.json:51-60`); client framework Bootstrap 5.3.8 (`package.json:19`), see CPT-CC-020. (corrected in review wave 2: version stated explicitly)
