# 02 — SERVER Subsystem Specification

Derived from legacy LegacyAdmin 5.2.3 source (`legacy-release`, hereafter `legacyadmin`). All evidence citations are `path:line` relative to the legacyadmin root. Classes live in `libraries/classes/Server/` and `libraries/classes/Controllers/Server/` (in 5.x the namespace `LegacyAdmin\…` maps onto `libraries/classes/…`).

Requirement types follow `README.md`: FR (functional), NFR (non-functional), SEC (security), UI (user interface/UX), DATA (data), CPT (compatibility/portability), DEP (deployment/operational), INT (interface/integration), CON (constraint). (corrected in review wave 1: the original header redefined CPT as "concept", DEP as "dependency" and INT as "integrity"; several existing IDs keep their historical type letter although their content is functional, e.g. NFR-SRV-001..005, UI-SRV-004, CPT-SRV-001, INT-SRV-003..005 - IDs are not renumbered.)

## 1. Server status / monitoring

- **CPT-SRV-001** The system shall treat the Server subsystem as a set of server-level pages (status, monitoring, query statistics, status variables, process list, replication, binary log, variables, engines, plugins, databases, privileges, collations, users) that operate against one currently selected MySQL/MariaDB server. Evidence: `libraries/classes/Server/Status/Data.php:1-30`, `libraries/classes/Controllers/Server/*`.

- **DATA-SRV-001** The system shall load the server status basis data by executing `SHOW GLOBAL STATUS` and, for derived calculations, `SHOW GLOBAL VARIABLES` on page load; if the `SHOW GLOBAL STATUS` query fails, the system shall expose a "data loaded = false" state instead of rendering status content (`SHOW GLOBAL VARIABLES` is always executed, also when the status query failed; a `primary_connection` POST value selects the replication connection for the embedded replication info). (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Data.php:353-374`.

- **FR-SRV-001** The system shall display the server status overview showing network traffic (`Bytes_received` + `Bytes_sent`), server uptime, and the start time of the server (computed as `UNIX_TIMESTAMP() - Uptime`). Evidence: `libraries/classes/Controllers/Server/Status/StatusController.php:60-74,102-105`.

- **FR-SRV-002** The system shall display per-direction traffic rows (Received, Sent, Total) with absolute values and per-hour values, computed with `hourFactor = 3600 / Uptime`. Evidence: `libraries/classes/Controllers/Server/Status/StatusController.php:110-152`.

- **FR-SRV-003** The system shall display connections statistics: max concurrent connections (`Max_used_connections`; count only, per-hour and percentage columns are always `---`), failed connection attempts (`Aborted_connects`), aborted clients (`Aborted_clients`) and total connections, the latter three with absolute, per-hour (`value * 3600/Uptime`, formatted with 4 significant digits and 2 decimals) and - for failed/aborted only - percentage-of-`Connections` values (2 decimals, suffixed `%`); percentages shall be shown as `---` when `Connections` is 0. Division by `Uptime` is not guarded against 0. (corrected in review wave 1) Evidence: `libraries/classes/Controllers/Server/Status/StatusController.php:157-205`. Verification (added in review wave 2): set `Uptime`, `Connections`, `Aborted_connects`, `Aborted_clients` in the status mock (e.g. 7200, 1000, 10, 20): per-hour Aborted_connects = 5, percentage = 1.00 %; with `Connections`=0 percentages render `---`; the `Max_used_connections` row shows `---` in the per-hour and percentage columns.

- **FR-SRV-004** When this server is acting as replication primary and/or replica, the status page shall additionally render the replication status tables for each role. Evidence: `libraries/classes/Controllers/Server/Status/StatusController.php:80-87`.

- **DATA-SRV-002** The system shall compute derived status indicators: `Key_buffer_fraction_%`, `Key_write_ratio_%`, `Key_read_ratio_%`, and `Threads_cache_hitrate_%`, and shall strip deprecated duplicates (`Com_prepare_sql`→`Com_stmt_prepare`, `Com_execute_sql`→`Com_stmt_execute`, `Com_dealloc_sql`→`Com_stmt_close`) when both old and new values exist. Evidence: `libraries/classes/Server/Status/Data.php:250-301,439-455`.

- **DATA-SRV-003** The system shall classify status variables into sections via an ordered allocation map matched by **substring containment** (`str_contains`, first matching entry wins - not strictly by prefix; e.g. `Com_`→com, `Innodb_`→innodb, `Qcache_`→qcache, `Slave_`/`Rpl_status`→repl, `Ssl_`→ssl, …) with `other` as fallback, and collect variables of the `com` section with value > 0 as "used queries" (excluding `Com_admin_commands`). (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Data.php:87-134,314-351,409`.

- **DATA-SRV-004** The system shall maintain a section dictionary (Com, SQL query, InnoDB, NDB, Handler, Query cache, Threads, Binary log, Temporary data, Delayed inserts, Key cache, Joins, Replication, Sorting, Tables, Transaction coordinator, Files, SSL, Other) used to group the "all status variables" view. Evidence: `libraries/classes/Server/Status/Data.php:141-165`.

- **INT-SRV-001** The `Server\Status\Data` object shall be read-only at runtime: its properties shall not be assignable externally (empty magic setter discarding writes). Evidence: `libraries/classes/Server/Status/Data.php:71-80`.

- **FR-SRV-005** (corrected in review wave 2: transport) The status variables page shall provide quick links per section/variable, including "Flush (close) all tables", "Show open tables" (`SHOW OPEN TABLES`), "Flush query cache", "Show replica hosts"/"Show primary status"/"Show replica status" (when replication is active), and links to InnoDB "Variables" and "InnoDB Status" pages. The flush links carry their parameters in `data-post` and are POSTed by the client script (see SEC-SRV-012 (g)); they are only revealed when the page script shows the "Related links" box for the selected category. Evidence: `libraries/classes/Server/Status/Data.php:180-239`, `templates/server/status/variables/index.twig:48-58`.

- **FR-SRV-006** The system shall display the list of all status variables grouped by section, each with: name, value, numeric-flag, doc link to the MySQL/MariaDB manual (except calculated `%` values), localized description for a known catalog of variables, and contextual links. Evidence: `libraries/classes/Controllers/Server/Status/VariablesController.php:60-141,231-518`.

- **FR-SRV-007** The status variables page shall evaluate threshold alerts per variable (e.g. `Aborted_clients`>0, `Innodb_row_lock_time_avg`>10, `Threads_cached`>0.95×`thread_cache_size`, `Qcache_free_blocks`>Qcache_total_blocks/5) and mark variables exceeding the threshold as alerted, and shall support a "only alerts" filter. Evidence: `libraries/classes/Controllers/Server/Status/VariablesController.php:88-99,113-118,136,167-224`.

- **UI-SRV-001** The status variables page shall provide category filtering (section), a text filter, an alerts-only filter, and a "don't format" toggle; the categories list shall contain only sections that actually have measurements. Evidence: `libraries/classes/Controllers/Server/Status/VariablesController.php:60-77,135-141`.

- **FR-SRV-008** The system shall accept flush commands from the status page limited to an allowlist (`STATUS`, `TABLES`, `QUERY CACHE`) and issue the corresponding `FLUSH <cmd>;` statement. Evidence: `libraries/classes/Controllers/Server/Status/VariablesController.php:56-58,149-162`. Verification (added in review wave 2): POST `flush=TABLES` to `/server/status/variables` as any authenticated user: `FLUSH TABLES;` appears in the server's query log; POST `flush=PRIVILEGES` (not in allowlist): no FLUSH statement is executed.

- **FR-SRV-009** The system shall provide a monitor page that loads a real-time charting UI (jqplot + chart.js assets), passing the list of numeric status variables, server time in ms, server OS name, superuser flag, and a local-database flag. Evidence: `libraries/classes/Controllers/Server/Status/MonitorController.php:38-74`.

- **INT-SRV-002** The monitor shall return real-time charting data as JSON on AJAX request; data points are typed and the server resolves them in a single batched round-trip: `statusvar` and `servervar` names are allowlist-filtered to `[a-zA-Z_]+` and fetched via `SHOW GLOBAL STATUS WHERE Variable_name='…' OR …` / `SHOW GLOBAL VARIABLES WHERE …`; `proc` returns the row count of `SHOW PROCESSLIST`; `cpu` returns OS load average (`idle`/`busy` split on Linux, `loadavg` otherwise); `memory` returns the named OS memory figure (0 if unknown). Names containing any character outside `[a-zA-Z_]` (including digits) are silently dropped by the allowlist filter. The response also carries `x` = server time in ms. (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Monitor.php:52-262`, `libraries/classes/Controllers/Server/Status/Monitor/ChartingDataController.php:39-55`.

- **CPT-SRV-002** The system shall obtain host load and memory figures through an OS-specific sysinfo abstraction (Linux, Windows/NT, SunOS; FreeBSD/DragonFly treated as Linux), falling back to an unsupported base implementation. Evidence: `libraries/classes/Server/SysInfo/SysInfo.php:19-79`.

- **FR-SRV-010** The monitor shall support querying the slow query log table `mysql.slow_log` for a time window, aggregating by start time/user/db/statement and summarizing counts by statement type; failure to query (e.g. log disabled) shall be reported as request status = false. Evidence: `libraries/classes/Server/Status/Monitor.php:264-336`, `libraries/classes/Controllers/Server/Status/Monitor/SlowLogController.php:39-65`.

- **FR-SRV-011** The monitor shall support querying the general query log table `mysql.general_log` for a time window, with optional filtering to `^(INSERT|SELECT|UPDATE|DELETE)` statement types and optional grouping of repeated `INSERT INTO table …` rows (suspension points appended); failure shall be reported as request status = false. Evidence: `libraries/classes/Server/Status/Monitor.php:338-472`, `libraries/classes/Controllers/Server/Status/Monitor/GeneralLogController.php:39-68`.

- **DATA-SRV-005** Long insert/update log entries (>220 chars) shall be truncated to 200 chars suffixed with `... [size]` formatted byte length. Evidence: `libraries/classes/Server/Status/Monitor.php:294-322,425-440`.

- **FR-SRV-012** The monitor shall allow setting a global variable via `SET GLOBAL name = value` (POST `varName`/`varValue`; the value is SQL-escaped and quoted unless numeric; the name is only validated against `[a-zA-Z0-9_]+`, i.e. it is **not** restricted to the four logging variables - non-matching names are silently ignored, no error) and shall always return the current values of `general_log`, `slow_query_log`, `long_query_time` and `log_output`. (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Monitor.php:474-501`, `libraries/classes/Controllers/Server/Status/Monitor/LogVarsController.php:39-59`.

- **FR-SRV-013** The monitor shall provide a query analyzer: the submitted query is executed with `SELECT … SQL_NO_CACHE` rewrite (plus `SET PROFILING=1` when profiling is supported), then `EXPLAIN` is run, and affected rows, explain output, profiling rows (`INFORMATION_SCHEMA.PROFILING WHERE QUERY_ID=1`), and any server error (`error` = last DB error text) are returned as JSON. The submitted statement is executed as-is for any statement type (only a leading `SELECT` is rewritten; optional POST `database` is selected first); `explain` is omitted when the EXPLAIN fails. (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Monitor.php:503-549`, `libraries/classes/Controllers/Server/Status/Monitor/QueryAnalyzerController.php:39-59`.

- **FR-SRV-014** The system shall display query statistics: total `Com_*` query count with per-hour/per-minute/per-second rates, per-statement counts sorted descending with per-hour value and percentage of total, and a pie chart where fractions < 2% with more than 6 segments are merged into an "Other" slice. Evidence: `libraries/classes/Controllers/Server/Status/QueriesController.php:54-104`.

- **INT-SRV-003** When status data could not be loaded, status overview, query statistics, status variables rendering, and advisor shall render a "data not loaded" state without calculations. Evidence: `libraries/classes/Controllers/Server/Status/StatusController.php:58`, `libraries/classes/Controllers/Server/Status/QueriesController.php:54`, `libraries/classes/Controllers/Server/Status/AdvisorController.php:29`.

## 2. Process list & kill query

- **FR-SRV-015** The system shall display the current process list as `SHOW PROCESSLIST` (or `SHOW FULL PROCESSLIST` when "full queries" is selected). Evidence: `libraries/classes/Server/Status/Processes.php:39-56`.

- **FR-SRV-016** The system shall optionally query `INFORMATION_SCHEMA.PROCESSLIST` when "show only active" (`showExecuting`), or when field ordering is requested, and filter with `WHERE state != ""` for active processes. Evidence: `libraries/classes/Server/Status/Processes.php:47-60`.

- **FR-SRV-017** The process list shall be sortable by clicking columns; sort requests (both `order_by_field` and `sort_order` POST values present) shall be executed as ``SELECT * FROM `INFORMATION_SCHEMA`.`PROCESSLIST` ORDER BY `<field>` <sort_order>``; the field is only backquoted (not checked against the offered column list Id, User, Host, Db, Command, Time, State, Progress, Info) and `sort_order` is concatenated **without any validation** - a defect to be fixed in a re-implementation (allowlist `ASC|DESC`). (corrected in review wave 1) Evidence: `libraries/classes/Server/Status/Processes.php:49-66,113-158`. Verification (added in review wave 2): POST `/server/status/processes` with `order_by_field=Time`, `sort_order=DESC`: the executed statement is ``SELECT * FROM `INFORMATION_SCHEMA`.`PROCESSLIST` ORDER BY `Time` DESC``; a new implementation receiving `sort_order=DESC; DROP ...` or `ASC,(SELECT 1)` must reject it (the legacy accepts it).

- **DATA-SRV-006** Each process row shall expose: Id, User, Host, Db (empty if unset), Command, Time, State (`---` if absent), Progress (MariaDB, rendered as percentage when `Stage`/`Max_stage` are present), and Info formatted SQL (truncated view unless "full" is active, `---` if absent). Evidence: `libraries/classes/Server/Status/Processes.php:70-110`.

- **UI-SRV-002** The Progress column shall be offered for sorting only when the server is MariaDB. Evidence: `libraries/classes/Server/Status/Processes.php:148-153`.

- **FR-SRV-018** The system shall support asynchronous refresh of the process list preserving the current filters (showExecuting, full, order_by_field, sort_order); non-AJAX refresh requests shall be ignored. Evidence: `libraries/classes/Controllers/Server/Status/Processes/RefreshController.php:24-39`.

- **FR-SRV-019** The system shall allow killing a running thread by Id via `DatabaseInterface::getKillQuery`, only in AJAX mode (route `POST /server/status/processes/kill/{id:\d+}`; the id is cast to int; the statement is `KILL <id>;`, or `CALL mysql.rds_kill(<id>);` on Amazon RDS for superusers), without any additional privilege check in LegacyAdmin (the MySQL server decides), reporting success or failure messages (corrected in review wave 1) ("Thread %s was successfully killed." / "LegacyAdmin was unable to kill thread %s…"). Evidence: `libraries/classes/Controllers/Server/Status/Processes/KillController.php:31-57`. Verification (added in review wave 2): AJAX POST `/server/status/processes/kill/123`: server receives `KILL 123;` and the JSON message is "Thread 123 was successfully killed."; a non-AJAX POST returns no body; `/kill/abc` is a route miss (404); killing a nonexistent id returns the "LegacyAdmin was unable to kill thread 123" message.

- **SEC-SRV-001** The process-list kill/refresh and monitor data APIs shall respond only to AJAX requests; direct (non-AJAX) invocation shall be a no-op without data leakage. Evidence: `libraries/classes/Controllers/Server/Status/Processes/KillController.php:33-35`, `libraries/classes/Controllers/Server/Status/Processes/RefreshController.php:34-36`, `libraries/classes/Controllers/Server/Status/Monitor/ChartingDataController.php:46-48`, `libraries/classes/Controllers/Server/Status/Monitor/GeneralLogController.php:51-53`, plus SlowLogController, LogVarsController and QueryAnalyzerController (same guard). All of these still run `selectDb('mysql')` for superusers before the AJAX check. (corrected in review wave 1)

## 3. Server variables (engine/system variables, SET)

- **FR-SRV-020** The system shall display all server system variables from `SHOW GLOBAL VARIABLES`, each with: name (underscores rendered as nbsp), value, doc link appropriate to MySQL or MariaDB, editability flag, and — when a session override differs from the global value — the session value shown as well (`SHOW SESSION VARIABLES`). Evidence: `libraries/classes/Controllers/Server/VariablesController.php:53-96`.

- **DATA-SRV-007** The system shall distinguish static (non-editable) variables from editable ones using a server-variable provider's static list. Evidence: `libraries/classes/Controllers/Server/VariablesController.php:62,80`.

- **UI-SRV-003** Numeric values of byte-typed variables (per variable-type metadata) shall be displayed both as raw number (title) and humanized size (e.g. KiB/MiB with 3-digit, 3-decimal formatting); other numeric values shall be number-formatted; non-numeric values shown escaped-literal, with the page indicating HTML-formatted values. Evidence: `libraries/classes/Controllers/Server/VariablesController.php:106-136`.

- **FR-SRV-021** The system shall support editing a global variable in AJAX mode via `SET GLOBAL <name> = <value>`, only when the variable name matches `^[a-zA-Z0-9_]+$`; otherwise a "Setting variable failed" error shall be returned. Evidence: `libraries/classes/Controllers/Server/Variables/SetVariableController.php:41,70-96`. Verification (added in review wave 2): AJAX POST `/server/variables/set/max_connections` with `varValue=200`: `SET GLOBAL max_connections = 200` is issued and `{variable: "200"}` returned; name `max-connections` or `a;b` returns `{error: "Setting variable failed"}`; `key_buffer_size` with `1MiB` is sent as `1048576`.

- **DATA-SRV-008** Values for byte-typed variables may be entered with units `kb|kib|mb|mib|gb|gib` (case-insensitive; 1 unit = 1024^n bytes) and shall be converted to plain byte numbers before applying; other non-numeric values shall be SQL-escaped and quoted. Evidence: `libraries/classes/Controllers/Server/Variables/SetVariableController.php:50-72`.

- **FR-SRV-022** After setting a variable, the system shall confirm the effective value by re-reading `SHOW GLOBAL VARIABLES WHERE Variable_name="…"` (the name is escaped and wrapped in **double** quotes, which breaks under `ANSI_QUOTES`) and return the formatted value (byte variables as humanized HTML, other numerics number-formatted, non-HTML values `htmlspecialchars`-escaped). (corrected in review wave 1) Evidence: `libraries/classes/Controllers/Server/Variables/SetVariableController.php:77-90`.

- **FR-SRV-023** The system shall provide an AJAX getter returning the raw current value of a single global variable (`SHOW GLOBAL VARIABLES WHERE Variable_name='<escaped>'`), with byte-typed values reformatted as humanized size; the response shall always be `text/html; charset=UTF-8`. Evidence: `libraries/classes/Controllers/Server/Variables/GetVariableController.php:32-61`.

- **CON-SRV-001** The ANSI_QUOTES mode shall be tolerated in variable access (applies to the GET path only; the SET path of FR-SRV-022 does not honor this): the read path uses single quotes exclusively to avoid double-quote interpretation. Evidence: `libraries/classes/Controllers/Server/Variables/GetVariableController.php:39-46`.

## 4. Replication (master/primary & replica enrollment, status)

- **FR-SRV-024** The system shall provide a server replication page that: (a) shows primary-replication configuration and the list of connected replica hosts when this server is a primary (`SHOW SLAVE HOSTS` / `SHOW REPLICAS` / `SHOW REPLICA HOSTS` by version), (b) shows replica configuration and status when this server is a replica, and (c) exposes forms to configure primary replication (DB multibox) and to change the replication primary. Evidence: `libraries/classes/Controllers/Server/ReplicationController.php:58-108`, `libraries/classes/ReplicationGui.php:73-104,129-220`.

- **CPT-SRV-003** Replication role detection and status shall be provided by `ReplicationInfo`, supporting multiple primary connections selected via the `primary_connection` POST parameter. Evidence: `libraries/classes/Controllers/Server/ReplicationController.php:58-62`, `libraries/classes/Server/Status/Data.php:353-358`.

- **FR-SRV-025** On a primary, the system shall provide an "add replica user" dialog that prefills username/hostname constraints (max lengths read from `mysql.user` column types), defaults for localhost/any/this-host, and allows creating a replication user on the primary. Evidence: `libraries/classes/ReplicationGui.php:380-444,351-378`.

- **FR-SRV-026** The system shall allow changing the replica's primary ("slave enroll"): entered credentials are SQL-escaped, stored in session (`m_username`, `m_password`, `m_hostname`, `m_port`), the primary is connected to test reachability (`connectToPrimary`), the current primary log position is read, and `replicaChangePrimary` re-points the replica; failures (connect, position read, change) each produce distinct error messages, success a "Primary server changed successfully to %s." message stored in session status `sr_action_status`/`sr_action_info`. Evidence: `libraries/classes/ReplicationGui.php:515-585`.

- **SEC-SRV-002** Changing the replication primary via GUI shall be disabled unless `$cfg['AllowArbitraryServer']` is enabled; a "Connection to server is disabled…" error shall be recorded otherwise. Evidence: `libraries/classes/ReplicationGui.php:460-465`.

- **SEC-SRV-003** Replication control requests shall be processed only for superusers (`ReplicationController` calls `handleControlRequest` only if `isSuperUser()`), shall require POST `sr_take_action`, and shall be dispatched by `replica_changeprimary` / `sr_replica_server_control` / `sr_replica_skip_error` (checked in this order). Only `sr_replica_server_control` is followed by an AJAX status (`Replication started successfully.` / `Replication stopped successfully.` / `Replication resetting successfully.` / `Success.` or the matching `Error ...` text) or a redirect to `/server/replication`; change-primary and skip-error report via the session status shown on the next page render. Thread control accepts only action `START`/`STOP` and control `SQL_THREAD`/`IO_THREAD`/none (case-insensitive); anything else yields result `-1` = error. (corrected in review wave 1) Evidence: `libraries/classes/ReplicationGui.php:449-513`. Verification (added in review wave 2): as a non-superuser POST `sr_take_action=1&sr_replica_server_control=1` to `/server/replication`: no replication statement is executed; as superuser with action `START` and control `SQL_THREAD` the statement `START REPLICA SQL_THREAD` (or `START SLAVE SQL_THREAD`) runs and the AJAX reply is "Replication started successfully."; action `DROP` yields the error.

- **FR-SRV-027** The system shall provide replica thread controls: START/STOP of IO_THREAD, SQL_THREAD, and both, plus RESET (implemented as STOP, `RESET REPLICA` (or legacy `RESET SLAVE` pre-MySQL 8.0.22 / MariaDB 10.5.1), START) and "skip error" (STOP, `SET GLOBAL SQL_REPLICA_SKIP_COUNTER = <n>` on MySQL >= 8.4.0 else `SQL_SLAVE_SKIP_COUNTER`, START; `<n>` = `sr_skip_errors_count * 1`, default 1, no range validation), each with success/error messages. Evidence: `libraries/classes/ReplicationGui.php:468-492,587-641`, `libraries/classes/Replication.php:51-71`. (corrected in review wave 1)

- **DATA-SRV-009** The replication status display shall list a fixed set of variables for primary (`primaryVariables`) and replica (`replicaVariables`), highlight IO/SQL Running states (`No` red, `Yes` green respectively), and widen comma lists for `Replicate_Do_DB`, `Replicate_Ignore_DB`, `Replicate_Do_Table`, `Replicate_Ignore_Table`, `Replicate_Wild_Do_Table`, `Replicate_Wild_Ignore_Table`. Evidence: `libraries/classes/ReplicationGui.php:272-344`.

- **FR-SRV-028** On the replica page, MariaDB multi-source status shall be fetched (`SHOW ALL REPLICAS STATUS` ≥10.5.1, legacy `SHOW ALL SLAVES STATUS`), and the page shall offer "reconfigure primary" and skip-error links. Evidence: `libraries/classes/ReplicationGui.php:135-140,186-199`.

- **DEP-SRV-001** Replication version branching: `SHOW REPLICAS` (MySQL ≥ 8.0.22), `SHOW REPLICA HOSTS` (MariaDB ≥ 10.5.1), legacy `SHOW SLAVE HOSTS`; `START/STOP/RESET REPLICA` for MySQL >= 8.0.22 or MariaDB >= 10.5.1 else `... SLAVE`; the skip counter variable `SQL_REPLICA_SKIP_COUNTER` only for MySQL >= 8.4.0 (otherwise `SQL_SLAVE_SKIP_COUNTER`); `SHOW REPLICA STATUS` / `SHOW SLAVE STATUS` with the 8.0.22 / 10.5.1 split; primary status via `SHOW BINARY LOG STATUS` (MySQL >= 8.2.0), `SHOW BINLOG STATUS` (MariaDB >= 10.5.2) or `SHOW MASTER STATUS`. (corrected in review wave 1) Evidence: `libraries/classes/ReplicationGui.php:79-85,594-600,630-634`, `libraries/classes/ReplicationInfo.php:116-140`, `libraries/classes/Query/Compatibility.php:260-272`.

## 5. Binary log display

- **FR-SRV-029** The system shall list binary log files via `SHOW BINARY LOGS` (keyed by Log_name) and display their contents: `SHOW BINLOG EVENTS [IN '<log>'] LIMIT <pos>,<cfg MaxRows>`, paginating with previous (pos - MaxRows; the `pos` parameter is omitted when pos <= MaxRows, i.e. page 1), next (pos + MaxRows, offered when the page returned >= MaxRows rows; `$cfg['MaxRows']` default 25) and "full queries" toggles (POST `is_full_query`). Inputs are read from POST only (route accepts GET and POST). (corrected in review wave 1) Evidence: `libraries/classes/Controllers/Server/BinlogController.php:38-129`. Verification (added in review wave 2): with 60 binlog events and `MaxRows`=25: the first page issues `SHOW BINLOG EVENTS LIMIT 0, 25`, its next link has `pos=25`, the second page's previous link omits `pos`; a `log` value not in `SHOW BINARY LOGS` never appears in the pagination links; GET parameters are ignored (POST only).

- **SEC-SRV-004** Only log names that exist in the `SHOW BINARY LOGS` result shall be propagated into the pagination/link URL parameters (allowlist check via `array_key_exists`). **Defect found in review:** the same POST `log` value is passed *unfiltered* to `getSqlQuery()` and concatenated into ``SHOW BINLOG EVENTS IN '<log>'`` without escaping, so the allowlist does not protect the executed statement; a re-implementation shall validate the name before building the SQL. (corrected in review wave 1) Evidence: `libraries/classes/Controllers/Server/BinlogController.php:38,59-61,69,121-126`. Verification (added in review wave 2): POST `log=x' OR '1'='1` (not in `SHOW BINARY LOGS`) to `/server/binlog`: the legacy builds ``SHOW BINLOG EVENTS IN 'x' OR '1'='1'`` (defect, visible in the general log); the new implementation must answer with a validation error and execute no statement containing the value.

- **INT-SRV-004** The position parameter shall be coerced to int and the row limit taken from `$cfg['MaxRows']`; paging anchors are generated accordingly (`has_previous` when pos>0, `has_next` when rows ≥ MaxRows). Evidence: `libraries/classes/Controllers/Server/BinlogController.php:56,77-92`.

- **NFR-SRV-001** The binary log page shall render the executed SQL and navigation with icon/text navigation links according to `TableNavigationLinksMode` display preference. Evidence: `libraries/classes/Controllers/Server/BinlogController.php:99,106`.
