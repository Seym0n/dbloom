# 13 — Features of current MySQL and MariaDB that the legacy SPEC lacks

**Status: PROPOSED, not approved.** Requested by the owner (`OPEN.md` item 20): write requirements for features of current MySQL and MariaDB versions that LegacyAdmin 5.2.3 does not cover. Nothing here describes LegacyAdmin; the requirements are for DBLoom (`*-TGT-2nn`).

**Basis and limits.**
- Target versions: the proposed minimum of ARCH-TGT-003 (MySQL 8.4 LTS, MariaDB 10.11 LTS) and the newer LTS releases that are tested with it (MySQL 9.7 LTS, MariaDB 11.8 LTS).
- Vendor facts were looked up on 2026-10-23 by web search (vendor manual pages where the search returned them, otherwise third-party sources). Each requirement says what is **verified**, what is **corrected** by the look-up, and what is still **unverified**. Unverified items shall be checked against the MySQL 8.4 / 9.7 and MariaDB 10.11 / 11.8 manuals before approval. Sources are listed in section 8.
- "Not in the SPEC" means: no match for the term in files 00 to 09 on 2026-10-23. The legacy code may still handle some of these in part (for example generated columns, DEP-DTB-001); the owner of each requirement shall check the code before approval.
- All features are subject to the scope decision (`OPEN.md` item 1).
- Every statement goes through the database adapter (ARCH-TGT-001) and its quoting and parameter rules (SEC-TGT-117). Capabilities differ by product and version, so each requirement is a strategy-selected variant (ARCH-TGT-002).

## 1. Capability model

- **FR-TGT-200** — **PROPOSED.** The adapter shall report, for each connected target, the features it supports (for example `check-constraint`, `invisible-index`, `system-versioning`, `sequence`, `explain-analyze`). Screens shall show a feature only when the target reports it, and shall otherwise hide it or show it disabled with the reason "not supported by this server version". Code outside the adapter shall not test the product name or version (ARCH-TGT-002). *Legacy basis:* none; the legacy code tests the family and version in many places (DEP-DTB-001). *Verification:* a contract test per adapter lists its capabilities; a screen test with a fake adapter that reports none of them shows no unsupported control.

## 2. Vector data and similarity search (dropped)

The owner dropped `FR-TGT-210` to `FR-TGT-214` (vector columns, vector indexes, similarity search and its link to the AI sidebar). The IDs are not reused. Reasons given: embeddings differ from model to model, so a search is only meaningful when the query vector comes from the same model as the stored ones, which DBLoom cannot guarantee. The look-up of 2026-10-23 also showed that similarity search is not available on MySQL Community (`DISTANCE()` is HeatWave/MySQL AI only) but is on MariaDB 11.8 and later. The look-up facts are kept in section 8 as background, in case vectors are revived.

## 3. Constraints and indexes

- **FR-TGT-220** — **PROPOSED.** `CHECK` constraints: the structure view shall list them with name, expression and, where the server has the flag, whether they are enforced; the user may add, drop and (where supported) toggle enforcement. *Verified:* MySQL enforces `CHECK` from 8.0.16 and reports `ENFORCED` YES/NO in `TABLE_CONSTRAINTS`; MariaDB enforces it from 10.2.1 (earlier versions ignored it). Both are below the proposed minimums, so the feature is always present. *Unverified:* whether MariaDB has a per-constraint enforcement flag. *Verification:* test per product.
- **FR-TGT-221** — **PROPOSED.** Expression (functional) indexes: where the target reports `functional-index`, the index editor shall allow an expression as a key part and the structure view shall show it. Where unsupported, the editor shall point to a generated column plus an index instead. *Verified:* the MySQL 8.4 `CREATE INDEX` grammar accepts `(expr)` as a key part, and `SHOW INDEX` shows `Column_name` NULL with the expression in `Expression`. *Unverified:* the 8.0.13 introduction version, and that MariaDB has no equivalent (it uses indexed virtual columns). *Verification:* test per product.
- **FR-TGT-222** — **PROPOSED.** Invisible or ignored indexes: the user may mark an index invisible (MySQL) or ignored (MariaDB 10.6 or later) and restore it, to test the effect of dropping it without losing it. The structure view shall show the state. *Verified:* MySQL uses `ALTER TABLE ... ALTER INDEX ... VISIBLE|INVISIBLE`, `{VISIBLE | INVISIBLE}` in `CREATE INDEX`, state visible in `SHOW INDEX`, not for primary keys; the optimizer flag `use_invisible_indexes` exists. MariaDB ignored indexes arrived in 10.6 (MDEV-7317, release notes). *Unverified:* the MariaDB statement syntax. *Verification:* test per product.
- **FR-TGT-223** — **PROPOSED.** Generated columns: stored and virtual generated columns shall be shown with their expression and editable with the product's keywords. *Legacy basis:* DEP-DTB-001 (partly covered; check the legacy code before approval).

## 4. Querying and analysis

- **FR-TGT-230** — **PROPOSED.** The SQL editor shall accept and run statements with common table expressions (`WITH`, recursive too), window functions and `JSON_TABLE`, and shall not refuse a statement because its own parser does not know the syntax. Syntax highlighting, formatting and completion shall include their keywords. If DBLoom's parser cannot analyse a statement, it shall send the statement unchanged and skip the analysis, not block it. *Verification:* a set of such statements runs on each product; an unknown but valid statement is not blocked.
- **FR-TGT-231** — **PROPOSED.** Explain and analyse: a query can be run with the server's explain, and where supported with the analysing form (MySQL `EXPLAIN ANALYZE`, MariaDB `ANALYZE`), shown as a tree and as the raw text or JSON. Because the analysing form executes the statement, it shall be offered for read statements only, unless the user explicitly confirms a statement that changes data, and the confirmation shall name the statement. *Verified:* MariaDB `ANALYZE` (since 10.1.0) accepts any statement `EXPLAIN` accepts, and `ANALYZE UPDATE`/`DELETE` really change data; MySQL `EXPLAIN ANALYZE` exists since 8.0.18, always uses TREE format, and the 8.4 manual's syntax block lists `SELECT` only. *Unverified:* whether MySQL 8.4 also analyses `UPDATE`/`DELETE`; until confirmed, treat it as read-only. *Verification:* test that a data-changing statement is not analysed without confirmation.
- **FR-TGT-232** — **PROPOSED.** Optimizer statistics: where supported, the table view shall show the histograms or persistent statistics of the server for each column and let the user refresh them (MySQL `ANALYZE TABLE ... UPDATE HISTOGRAM`; MariaDB engine-independent statistics). *Verified:* MySQL syntax `ANALYZE [NO_WRITE_TO_BINLOG | LOCAL] TABLE t UPDATE HISTOGRAM ON col [, col] [WITH N BUCKETS] [{MANUAL | AUTO} UPDATE]` and `DROP HISTOGRAM ON col`; one table per statement; needs `SELECT` and `INSERT`; not for views; histograms are stored in the data dictionary. MariaDB stores them in `mysql.column_stats`, the type is set by `histogram_type`, and they are not gathered automatically (collection needs a full table scan with `ANALYZE TABLE`). *Unverified/conflicting:* the MariaDB version that added JSON-format histograms (sources give 10.7 preview and 10.8); the exact `PERSISTENT FOR` syntax. *Verification:* test per product.
- **FR-TGT-233** — **PROPOSED.** Performance views (read-only): a screen shall present the most useful data of `performance_schema` and the `sys` schema where they exist and the user may read them: slowest and most frequent statements, waits, unused indexes and tables without a primary key. It shall show a clear message when the schema is missing or the user lacks the privilege, and shall never change the instrumentation settings. *Unverified:* the search found nothing on the `sys` schema in MariaDB (my recollection of 10.6 is unconfirmed) or on `performance_schema` defaults; the screen shall therefore rely on the capability check, not on a version. *Verification:* test with a user who lacks the privilege and on a server without the schema.

## 5. Product-specific features

- **FR-TGT-240** — **PROPOSED.** System-versioned tables (MariaDB 10.3 or later): the structure view shall show whether a table is versioned; the user may add and remove versioning; the browse screen shall offer "as of" a point in time and a row-history view using `FOR SYSTEM_TIME`. *Verified:* support since MariaDB 10.3.4; `FOR SYSTEM_TIME ALL` shows current and historical rows; time partitioning is supported. *Unverified:* the statements to add and remove versioning, and limits. *Verification:* test on MariaDB; hidden on MySQL (FR-TGT-200).
- **FR-TGT-241** — **PROPOSED.** Sequences (MariaDB 10.3 or later): list, create, alter, drop and show the current value, in the same way as tables. *Verified (weakly):* sequences came with MariaDB 10.3 (beta announcement, as an alternative to `AUTO_INCREMENT`). *Unverified:* the `CREATE SEQUENCE` syntax. *Verification:* test on MariaDB; hidden on MySQL.
- **FR-TGT-242** — **PROPOSED.** Types: the column editor shall offer the types of the connected server that the legacy editor lacks, including `UUID` and `INET6` (MariaDB) and `JSON` (both products), with a display and input that fit the type. A `JSON` cell shall be shown formatted, validated on edit and, if the user opens it, as a collapsible tree; the content is untrusted and displayed as text (SEC-TGT-112). *Legacy basis:* UUID is partly covered by DEP-DTB-001. *Verified:* MariaDB `INET6` since 10.5; MariaDB `UUID` type since 10.7 (Community; backported to Enterprise 10.6.9-5); MariaDB `JSON_TABLE` since 10.6.0. *Unverified:* that MySQL has no `UUID` or `INET6` type; the MySQL `JSON_TABLE` version (8.0.4). *Verification:* create, edit and show a column of each type.
- **FR-TGT-243** — **PROPOSED.** Defaults: new databases and tables shall default to `utf8mb4` with the server's default collation for it, unless the user picks another, and the character set shown shall come from the server. Where a `TIMESTAMP` column has the extended range (MariaDB 11.8), the editor shall show the valid range of the connected server. *Verify:* defaults and range per version. *Verification:* test that a new table is created with the expected character set.

## 6. Considered and not proposed for the first release

| Feature | Reason |
|---|---|
| JavaScript stored programs (MySQL 9.x multilingual engine) | Introduced in 9.0 as an Enterprise feature; a conference abstract lists it for 9.7 Community, and Oracle's 9.7 announcement says Community gained "significant new capabilities". Unresolved without Oracle's 9.7 release notes. Add when confirmed and wanted (candidate for `FUTURE.md`). |
| Vector columns, vector indexes and similarity search | Dropped by the owner (section 2): embeddings differ from model to model; not available on MySQL Community. Revive via `FUTURE.md` if wanted. |
| Roles, resource groups, replication changes of 8.x and 9.x | Not yet analysed against the legacy server pages (`02-server.md`). Needs the scope decision first. |
| Spatial reference systems of MySQL 8.x | Legacy GIS support is described in `04-io-formats.md`; the delta is not yet compared. |
| Cluster, Galera and group replication management | Out of scope for a table and data tool; revisit with item 1. |

## 7. Open points

- The scope decision (`OPEN.md` item 1) decides which of these ship in the first release.
- Items marked **unverified** need checking against the MySQL and MariaDB manuals. 
- Oracle's 9.7 release notes should be read to settle the Community versus Enterprise split (JavaScript stored programs).
- The legacy code is not yet read for generated columns, UUID, JSON and the SQL parser's coverage of CTEs and window functions.

## 8. Sources of the look-up (2026-10-23)

Vector background (feature dropped, section 2): MariaDB 11.8 has `VECTOR INDEX` in `CREATE TABLE` (options `M`, `DISTANCE`), `VEC_DISTANCE_EUCLIDEAN()`, `VEC_DISTANCE_COSINE()`, `VEC_FromText()`, `VEC_ToText()`. MySQL 9.x has the `VECTOR` type with `STRING_TO_VECTOR()`, `VECTOR_TO_STRING()` and `VECTOR_DIM()`; `DISTANCE()` is HeatWave/MySQL AI only; a Community vector index was not found.

Vendor manuals (as returned by the search): MySQL 9.5 vector functions (`https://dev.mysql.com/doc/refman/9.5/en/vector-functions.html`), MySQL 8.4 `ANALYZE TABLE`, `EXPLAIN`, invisible indexes and `CREATE INDEX` pages (`https://dev.mysql.com/doc/refman/8.4/en/`), MySQL 8.0 `TABLE_CONSTRAINTS` page, MariaDB Vector Overview (`https://mariadb.com/kb/en/vector-overview`), MariaDB `ANALYZE` statement, system-versioned tables, `JSON_TABLE`, histogram-based statistics and constraint pages (`https://mariadb.com/kb/en/`), MariaDB 10.5.0 and 10.6.0 release notes.
Third-party: Percona blog on `DISTANCE()` in Percona Server 9.7, heise and other summaries of MySQL 9.0, a COSCUP 2026 abstract, blogs on MariaDB 11.8.
