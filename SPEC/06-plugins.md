## 6.1 Concepts (CPT)

- **CPT-PLG-001 Plugin family taxonomy.** The system distinguishes plugin families: Export, Import, Schema (also named "Schema export"), Transformations (Input / Output), Authentication, Authentication-2FA (TwoFactor), and Import-Upload. Each family lives in its own sub-directory of `libraries/classes/Plugins/` and has a dedicated abstract base class; Export (`libraries/classes/Plugins/ExportPlugin.php:24`), Import (`libraries/classes/Plugins/ImportPlugin.php:21`), Schema (`libraries/classes/Plugins/SchemaPlugin.php:23`), Transformations (`libraries/classes/Plugins/TransformationsPlugin.php:16`). (clarified in review wave 1)
  Review wave 1 note: the Authentication family is represented by the abstract `AuthenticationPlugin` (`Plugins/AuthenticationPlugin.php`) and the concrete classes in `Plugins/Auth/`; it is not discovered by directory scan but by `Plugins::getAuthPlugin()` (SEC-PLG-006). Two-factor plugins extend `TwoFactorPlugin`; Import-Upload handlers implement `UploadInterface`. Only the Export, Import and Schema families are enumerated by `Plugins::getPlugins()` (`Plugins.php:119-150`).
- **CPT-PLG-002 Base contract.** Every enumerable plugin implements interface `LegacyAdmin\Plugins\Plugin`, which requires exactly three members: `getName(): string` (non-empty lowercase), `getProperties(): PluginPropertyItem`, and `static isAvailable(): bool` (`libraries/classes/Plugins/Plugin.php:9-19`).
- **CPT-PLG-003 Properties object.** Each plugin returns a `PluginPropertyItem` (subclass: `ExportPluginProperties` / `ImportPluginProperties` / `SchemaPluginProperties`) exposing display *text*, *extension*, MIME *type*, options *root group* and *options text*, plus `getForceFile()` and `getPropertyType()` (`libraries/classes/Properties/Plugins/PluginPropertyItem.php:20-170`).
- **CPT-PLG-004 Options tree.** Plugin options are modeled as a tree of property objects: `OptionsPropertyRootGroup` → `OptionsPropertyMainGroup` → leaf items (`Bool/Text/Number/Radio/Select/Hidden/MessageOnly/Doc`) with optional `OptionsPropertySubgroup` nesting; groups implement `Countable` (`libraries/classes/Properties/Options/OptionsPropertyGroup.php:22-101`, `libraries/classes/Properties/Options/OptionsPropertyItem.php:18-55`).
- **CPT-PLG-005 MIME-driven transformation naming.** A transformation is identified by file name `MIMEType_MIMESubtype_Name.php` inside `libraries/classes/Plugins/Transformations/` (root = output-transform legacy, `Input/`, `Output/`), from which the MIME type `parts[0]/parts[1]` and name `parts[2]` are derived (`libraries/classes/Transformations.php:155-177`).

## 6.2 Plugin interface contract & lifecycle (FR)

- **FR-PLG-001 Plugin instantiation by convention.** The system shall instantiate a plugin of a given type/format by mapping `"export","sql"` → class `LegacyAdmin\Plugins\Export\ExportSql`, using the class name template `LegacyAdmin\Plugins\{Type}\{Type}{Format}` with first-letter case normalization; it shall return `null` when the class does not exist (`libraries/classes/Plugins.php:60-73`). (clarified in review wave 1)
  Review wave 1 detail: both `type` and `format` are normalized with `mb_strtoupper(first char) . mb_strtolower(rest)`, so `phparray` maps to `ExportPhparray` and `texytext` to `ExportTexytext`; the format string is not otherwise validated here (callers apply `Core::securePath`, SEC-PLG-001). The class is only checked with `class_exists` (autoload), not with `is_subclass_of Plugin`/`isAvailable()`, so `getPlugin()` can return a plugin that the enumeration would hide (for example `ExportXml` at server scope).
  Verification: call `Plugins::getPlugin('export', 'phparray')` and `('export', 'texytext')` and assert `ExportPhparray` / `ExportTexytext` instances; call `('export', 'nosuch')` and assert `null`; call `('export', 'xml')` at server scope and assert an `ExportXml` object is still returned although the chooser hides it. (added in review wave 2)
- **FR-PLG-002 Context injection via `$plugin_param`.** Before plugin instantiation and enumeration, the system shall store the caller's context in global `$plugin_param` (export: `{export_type, single_table}`; import: context string; schema: none) so plugin property builders can react to it (`libraries/classes/Plugins.php:62-64,84,98`).
- **FR-PLG-003 Enumeration by directory scan.** The system shall discover plugins of a family by scanning `ROOT_PATH . libraries/classes/Plugins/{Type}` with `FilesystemIterator`, admitting only readable PHP files whose basename starts with the family name (e.g. `Export…`) (`libraries/classes/Plugins.php:119-137`). (clarified in review wave 1)
  Review wave 1 detail: names that do not start with the family prefix are skipped, so `Export/Helpers/` (directory), `Import/Upload/` (directory), `Import/AbstractImportCsv.php` and `Import/ShapeFileImport.php` are never candidates; for Schema the prefix is `Schema`, so `ExportRelationSchema.php`, `RelationStats.php` and `TableStats.php` are skipped. An unreadable directory yields an empty list (`catch Throwable`). Candidates are instantiated with `new $class()` in directory-iteration order and then sorted (FR-PLG-006).
  Verification: add a stub class file `Plugins/Export/ExportFoo.php` (implements `Plugin`, `isAvailable()` true) and assert it appears in `Plugins::getExport(...)`; add `Plugins/Export/Helper.php` and a sub-directory and assert neither appears; make the directory unreadable and assert an empty list instead of an exception. (added in review wave 2)
- **FR-PLG-004 Admittance gate.** A scanned file is instantiated as a plugin only if the derived class exists, is a subclass of `LegacyAdmin\Plugins\Plugin`, and `class::isAvailable()` is `true` (`libraries/classes/Plugins.php:140-144`).
  Verification: add a stub whose `isAvailable()` returns false and one that does not implement `Plugin`; assert neither is listed while a normal plugin is. (added in review wave 2)
- **FR-PLG-005 Availability conditions.** Plugins may override `isAvailable()` to express runtime conditions: e.g. `ExportPdf` is available only when TCPDF exists and curl is loaded (`libraries/classes/Plugins/Export/ExportPdf.php:334-337`), `ExportXml` only in database/table scope where `$db` is set (`libraries/classes/Plugins/Export/ExportXml.php:551-557`), and `ImportLdi` only in table scope (`libraries/classes/Plugins/Import/ImportLdi.php:187-190`); base classes default to `true` (`libraries/classes/Plugins/ExportPlugin.php:377-380`, `ImportPlugin.php:93-96`, `SchemaPlugin.php:95-98`). The complete availability matrix is FR-PLG-057; XML export and PDF export/schema are therefore not always available (clarified in review wave 2).
- **FR-PLG-006 Sorted presentation.** The enumerated plugin list shall be sorted by the localized property text of each plugin (case-insensitive `strcasecmp`) before being handed to the UI (`libraries/classes/Plugins.php:147-149`).
- **FR-PLG-007 Entry points.** The manager shall expose type-bound enumerators: `getExport(type, singleTable)` (`Plugins.php:80-87`), `getImport(type)` (`Plugins.php:94-101`), and `getSchema()` (`Plugins.php:106-109`).
- **FR-PLG-008 Export plugin lifecycle.** An export plugin's final constructor shall (a) fetch `relation`, `export`, `transformations` services from the DI container, (b) run the plugin's `init()`, then (c) call the plugin-implemented `setProperties()` and store the result (`libraries/classes/Plugins/ExportPlugin.php:45-52`). Import plugins follow the same init→setProperties lifecycle with a locally constructed `Import` service (`libraries/classes/Plugins/ImportPlugin.php:33-38`); schema plugins likewise (`libraries/classes/Plugins/SchemaPlugin.php:32-36`).
- **FR-PLG-009 Export plugin mandatory output methods.** `ExportPlugin` shall declare as abstract: `exportHeader()`, `exportFooter()`, `exportDBHeader()`, `exportDBFooter()`, `exportDBCreate()`, and `exportData()` (`libraries/classes/Plugins/ExportPlugin.php:57-105`).
- **FR-PLG-010 Export plugin optional capabilities.** `ExportPlugin` shall provide no-op default implementations plugins may override: `exportRoutines()`, `exportEvents()`, `exportRawQuery()`, `exportStructure()`, `exportMetadata()`, `getTableDefStandIn()`, `getTriggers()` (`libraries/classes/Plugins/ExportPlugin.php:118-227`).
- **FR-PLG-011 Export plugin alias helpers.** All export plugins shall share alias-resolution helpers: `initAlias()`, `getAlias()` (db/table/col search) and `getRelationString()` producing `ForeignTable (ForeignField)` (`libraries/classes/Plugins/ExportPlugin.php:265-375`).
- **FR-PLG-012 Import plugin contract.** `ImportPlugin` shall declare abstract `doImport(?File $importHandle, array &$sql_data)` carrying the whole format logic, and expose `getDbnameAndOptions()` to pick target DB and suppress `CREATE DATABASE` when a DB is already selected (`libraries/classes/Plugins/ImportPlugin.php:52-91`).
- **FR-PLG-013 Schema plugin contract.** `SchemaPlugin` shall declare abstract `exportSchema($db)` and `setProperties(): SchemaPluginProperties`, and provide shared option builders `addCommonOptions()` ("Show color", "Only show keys") and `getPaperSizeArray()` (`libraries/classes/Plugins/SchemaPlugin.php:58-93`).
- **FR-PLG-014 Option validation by known-parameters whitelist.** At run time the entity-side controllers shall accept only a whitelist of plugin POST parameters into `$GLOBALS` (e.g. `sql_structure_or_data`, `csv_*`, `latex_*`, `aliases`) before invoking the plugin (`libraries/classes/Controllers/Export/ExportController.php:192-223`). If unknown, such POST data is ignored. (corrected in review wave 1)
  Review wave 1 detail: the controller copies only the POST keys of a fixed list of names into `$GLOBALS` (keys not in the list are silently ignored). The list contains, per format, every option documented in 04-io-formats FR-IOX-071 to FR-IOX-083, but **not**: `csv_replace` (a comment says it "should have been here" - it is import-only), `pdf_report_title` (read from `$_POST` directly by `ExportPdf.php:52`), `xml_export_struc`, and `sql_include_indexes` (does not exist in 5.2.3). A new export option therefore requires editing `Controllers/Export/ExportController.php:~100-223`. For imports the whitelist is by prefix: only POST keys matching `^<format>_` and `^force_file_` are promoted to globals (`ImportController.php:250-258`).
  Verification: post an export with `sql_auto_increment=1`, `csv_separator=;`, `foo_bar=1`, `pdf_report_title=X` and `csv_replace=1`; assert the first two reach the plugin as globals, `foo_bar` is ignored, `pdf_report_title` is still honored (read from `$_POST` directly) and `csv_replace` has no effect on export; for import post `csv_terminated` and `sql_x`, with `format=csv`, and assert only `csv_*` and `force_file_*` keys are promoted. (added in review wave 2)
- **FR-PLG-015 Plugin option propagation.** The option values submitted through the generated form (`name="{plugin_name}_{option_name}"`) shall be read back directly as POST/REQUEST keys of that name, both during rendering (`Plugins::checkboxCheck`, `Plugins::getDefault`) and execution (`libraries/classes/Plugins.php:177-233`).
- **FR-PLG-016 Option defaults resolution.** `Plugins::getDefault(section, opt)` shall resolve an option default with priority: `$_GET` value (repopulate) → `$_REQUEST` value when `timeout_passed` → `$GLOBALS['cfg'][section][opt]`, substituting global `str*` locale placeholders and HTML-encoding the result (`libraries/classes/Plugins.php:202-233`). (clarified in review wave 1)
  Review wave 1 detail: `getDefault` returns `''` when the config key is missing; otherwise every token matching `str[A-Z][A-Za-z0-9]*` is replaced by the same-named global (the localized `strLatex...` strings) before `htmlspecialchars` (`Plugins.php:202-233`). `checkboxCheck` returns the literal string ` checked="checked"` or `''`.
- **FR-PLG-017 Checkbox state resolution.** `Plugins::checkboxCheck(section, opt)` shall mark a checkbox as checked when the GET repopulation key is present, or when a timeout-repopulated request value or configured `$cfg[section][opt]` default exists (`libraries/classes/Plugins.php:177-190`).

## 6.3 Property groups & option rendering (FR / UI / DATA)

- **FR-PLG-018 Plugin chooser data.** The system shall produce a plugin choice list with per-plugin `name`, localized `text`, `is_selected` (matching the requested default) and `force_file` flag (`libraries/classes/Plugins.php:241-256`).
- **FR-PLG-019 Default selection precedence (export).** The default chosen format shall be `$_GET['what']` if present, otherwise the configured `$cfg['Export']['format']` (default `'sql'`, `libraries/config.default.php:1515-1517`) resolved via `Plugins::getDefault('Export','format')` (`libraries/classes/Export/Options.php:134-135`).
- **FR-PLG-020 Default selection (import).** The default import format shall default to `$cfg['Import']['format']` = `'sql'` (`libraries/config.default.php:2108-2110`), with dropdowns built the same way for server (`libraries/classes/Controllers/Server/ImportController.php:82-83`), database and table import pages. (clarified in review wave 1)
  Review wave 1 detail: the import page default is `$_GET['format']` when present, else `Plugins::getDefault('Import','format')` (`Controllers/Server/ImportController.php:81`); the import side thus uses the `format` key whereas the export side uses `what` (FR-PLG-019). `skip_queries` default is obtained the same way (`:84`).
- **FR-PLG-021 Rendered options surface.** The system shall render one options `<div id="{plugin}_options" class="format_specific_options">` per plugin with a `<h3>` title and, when the plugin declares no visible items ("This format has no options" fallback), shall still emit the container (`libraries/classes/Plugins.php:553-596`). Hidden-only option sets count as "no options" (`Plugins.php:576-590`). (corrected in review wave 1)
  Review wave 1 correction: the "no options" determination is evaluated per main group and reset for each group, so the final value reflects only the **last** main group of the plugin; a plugin whose last main group contains only `HiddenPropertyItem`s therefore prints "This format has no options" (class `card-text`) even if earlier groups were rendered (`Plugins.php:553-593`). Plugins with no options object (for example MediaWiki/XML/SHP importers) always print the fallback text.
- **FR-PLG-022 Recursive group rendering.** Options rendering shall recurse: main groups render as `<div><h5>` heading + `<ul class="list-group">`, subgroups render as nested `<li><ul>` with optional subgroup-header property (`libraries/classes/Plugins.php:269-357`).
- **FR-PLG-023 Leaf item widget mapping.** Property classes map to form widgets: `BoolPropertyItem` → checkbox switch with optional forced interlock `onclick` guard, `HiddenPropertyItem` → hidden input with default value, `MessageOnlyPropertyItem` → plain text, `RadioPropertyItem` → radio set with default checked, `SelectPropertyItem` → `<select>` with default selected, `TextPropertyItem` → text input with `size`/`maxlength`, `NumberPropertyItem` → `<input type=number min=0>`; unknown classes are skipped (`libraries/classes/Plugins.php:385-542`). (corrected in review wave 1: `DocPropertyItem` is not silently skipped - its branch `echo`es the class name; see UI-PLG-003. Checkbox `value` is the literal `something`.)
- **FR-PLG-024 Inline documentation links.** Property items exposing `getDoc()` shall render MySQL documentation links: 3-element doc arrays render as doc link with anchor, 1-element as FAQ reference rather than doc-link, otherwise a plain doc link (`libraries/classes/Plugins.php:346-357`).
- **UI-PLG-001 Option element naming.** Every option form element shall be identified `checkbox_ / radio_ / select_ / text_ / number_ {plugin}_{option}` and named `{plugin}_{option}` so that values propagate back under that composite key (`libraries/classes/Plugins.php:393-535`).
- **UI-PLG-002 Schema plugins also render options.** Schema plugins reuse the same property rendering pipeline ("Schema" section), e.g. in the Designer export dialog (`libraries/classes/Database/Designer.php:143-144`).

- **INT-PLG-004 Plugin format normalization.** POST `format` for import is normalized to `'sql'` under skip/partial retry conditions (`libraries/classes/Controllers/Import/ImportController.php:86,173,204,209`). (corrected in review wave 1)

## 6.5 Security & robustness of plugin dispatch (SEC)

- **SEC-PLG-001 Path sanitization of dynamic plugin keys.** The `what` (export format key) and `format` (import format key) coming from requests shall be passed through `Core::securePath()` / sanitized before being mapped to class names used in any include or instantiation logic (`libraries/classes/Controllers/Export/ExportController.php:225-235`, `libraries/classes/Controllers/Import/ImportController.php:86,261`).
- **SEC-PLG-002 Local import file sanitization.** See FR-IOX-048 (owner: upload directory, `Core::securePath()` and symlink rules for `local_import_file`) (`libraries/classes/Controllers/Import/ImportController.php:456-457`). (cross-reference introduced in review wave 2)
- **SEC-PLG-003 Whitelist guardrails.** See FR-PLG-014 (owner; same code and evidence). Security rationale kept here (cross-reference introduced in review wave 2): dangerous/trusted plugin options shall only be honored from a fixed allow-list of POST parameters (e.g. `sql_include_indexes`, `sql_auto_increment`, `csv_replace`, `latex_*`, `aliases`) (`libraries/classes/Controllers/Export/ExportController.php:192-223`). (corrected in review wave 1)
  Review wave 1 correction: the examples `sql_include_indexes` and `csv_replace` are not in the allow-list (`sql_include_indexes` does not exist anywhere in 5.2.3; `csv_replace` is read from `$_POST` by the CSV importer, not the exporter). Allow-listed examples are `sql_auto_increment`, `sql_simple_view_export`, `latex_*`, `aliases` (`Controllers/Export/ExportController.php:~100-223`). Also note the allow-list limits only what is copied to `$GLOBALS`; `pdf_report_title` and `csv_replace`-style options are still read from `$_POST`/`$_REQUEST` directly by plugins.
- **SEC-PLG-004 Transformation file existence check.** Before resolving a stored transformation, the system shall require the physical file `libraries/classes/Plugins/Transformations/{file}` to exist before instantiating and invoking it (`libraries/classes/Display/Results.php:2578-2584`, `libraries/classes/Controllers/Table/ReplaceController.php:272-276`).
- **SEC-PLG-005 External-program allowlist.** The *External* transformation family shall be no-op unless the administrator edits the plugin to allow specific programs; user-supplied options may carry arguments only for those allow-listed binaries, with a code-level warning about output redirection injection (`libraries/classes/Plugins/Transformations/Abs/ExternalTransformationsPlugin.php:83-118`). (clarified in review wave 1)
  Review wave 1 detail: the allowed program table is `$allowed_programs = []` inside `applyTransformation`; with an empty table the plugin returns the buffer unchanged. The program index comes from `options[0]` (fallback to program 0); `options[1]` (extra command line) is deprecated and triggers `E_USER_DEPRECATED` when non-empty, yet is still appended to the command string; output is passed through `htmlspecialchars` when `options[2]` equals `1` or `2`; `applyTransformationNoWrap` is true unless `options[3]` is set to a value other than empty/`1` (`Abs/ExternalTransformationsPlugin.php:50-128`).
  Verification: apply the External transformation to the value `abc` with the shipped code (empty `$allowed_programs`) and assert the output is `abc` and no process is started; with a stub program table assert only the indexed program runs, that a non-empty `options[1]` raises the deprecation notice and that output is HTML-escaped when `options[2]` is 1. (added in review wave 2)
- **SEC-PLG-006 Authentication-plugin dispatch trust.** `Plugins::getAuthPlugin()` shall construct `LegacyAdmin\Plugins\Auth\Authentication{Ucfirst(auth_type)}` and hard-fatal with "Invalid authentication method set in configuration" when no such class exists (`libraries/classes/Plugins.php:598-616`). (clarified in review wave 1)
  Review wave 1 detail: the class name is `Authentication` + `ucfirst(strtolower($cfg['Server']['auth_type']))`, so the valid values are `config` (-> `AuthenticationConfig`), `cookie`, `http`, `signon`; any other value ends in the fatal error `Invalid authentication method set in configuration: <value>` (`Plugins.php:598-616`).
  Verification: set `auth_type` to `cookie`, `Config`, `http`, `signon` and assert the respective `Authentication*` class is returned (case-insensitive); set it to `foo` and assert the fatal error "Invalid authentication method set in configuration: foo". (added in review wave 2)

## 6.6 Transformations framework (FR / CPT / DATA)

- **FR-PLG-025 Transformation contract.** Every transformation implements `TransformationsInterface` with static `getInfo()`, `getMIMEType()`, `getMIMESubtype()`, `getName()` (`libraries/classes/Plugins/TransformationsInterface.php:14-43`) and extends `TransformationsPlugin`, providing `applyTransformation($buffer, array $options, ?FieldMetadata $meta)`, optional `applyTransformationNoWrap(array $options)` (default `false`) and `getOptions($options, $defaults)` merging passed options over defaults when non-empty (`libraries/classes/Plugins/TransformationsPlugin.php:16-63`). (corrected in review wave 1)
  Review wave 1 correction: `TransformationsPlugin::getOptions($options, $defaults)` iterates over the **keys of `$defaults`** only: for each default key the passed value is used when it is set and not the empty string, otherwise the default; passed options with keys not present in the defaults are dropped (for example a fourth option for a three-element default is lost), which is why `Inline`'s defaults also contain the keys `wrapper_link` and `wrapper_params` (`Plugins/TransformationsPlugin.php:50-63`; `config.default.php:3095-3102`).
  Verification: unit-test `TransformationsPlugin::getOptions`: `([], ['x','y'])` returns `['x','y']`; `(['a'], ['x','y'])` returns `['a','y']`; `(['a','b','c'], ['x','y'])` returns `['a','b']` (extra option dropped); `(['', 'b'], ['x','y'])` returns `['x','b']` (empty string falls back to the default). (added in review wave 2)
- **FR-PLG-026 I/O transformation state.** `IOTransformationsPlugin` adds `getInputHtml()`, `getScripts()`, `getError()`, `isSuccess()`, `reset()` with success/error state fields (`libraries/classes/Plugins/IOTransformationsPlugin.php:14-96`).
- **FR-PLG-027 Pre-run / class resolution.** A stored transformation string (`e.g. output/image_jpeg__inline.inc.php` legacy or `output/Image_JPEG_Inline.php`) is mapped via `Transformations::getClassName`, which strips the first 18 chars of the pseudo-path and converts to the PSR-4 class name (`libraries/classes/Transformations.php:191-198`), optionally with subdir capitalization (`ucfirst`) when a `/`-separated dir prefix exists (`libraries/classes/Transformations.php:320-333`). (clarified in review wave 1)
  Review wave 1 correction: `Transformations` methods are instance methods (service `Transformations`), not static (`new Transformations()` / DI), so the call sites are `$transformations->getClassName(...)`. Stored transformation values have the form `<Subdir>/<Mime_Subtype_Name>.php` for example `Output/Text_Plain_Json.php` or `Input/Text_Plain_JsonEditor.php`; `getClassName('libraries/classes/Plugins/Transformations/Output/Text_Plain_Json.php')` strips the first 18 characters (`libraries/classes/`), appends to `LegacyAdmin\` and replaces `/` with `\`. Legacy values such as `output/image_jpeg__inline.inc.php` are repaired in `getMime()` by capitalizing the directory and running `fixUpMime` (`Transformations.php:191-198, 320-333`).
- **FR-PLG-028 Options-string parsing.** A transformation options string shall be parsed by splitting on commas, honoring single-quote wrapping and embedded commas (`'option ,, quoted',abd,'2,3',`) and applying `stripslashes` per item (`libraries/classes/Transformations.php:68-104`). ### 6.10.3 Registry, wrapper and availability

- **FR-PLG-055 Concrete class to MIME / name table** (added in review wave 1) — Each concrete class declares `getMIMEType()` / `getMIMESubtype()` (title-cased) from which the stored/displayed MIME is `<type>/<subtype>`: `Image_JPEG_*` -> `Image/JPEG`; `Image_PNG_Inline` -> `Image/PNG`; `Application_Octetstream_*` -> `Application/OctetStream`; `Text_Octetstream_Sql` -> `Text/Octetstream`; every `Text_Plain_*` -> `Text/Plain`. The display name is the abstract class's `getName()` (for example `Bool2Text`, `Date Format`, `Download`, `External`, `Formatted`, `Hex`, `ImageLink`, `Inline`, `Long To IPv4`, `PreApPend`, `Regex Validation`, `SQL`, `Substring`, `Image Link`, `TextLink`, `Text file upload`, `Image upload`); the plugins that extend `TransformationsPlugin` directly override `getName()`: `Binary To IPv4/IPv6`, `IPv4/IPv6 To Binary`, `IPv4/IPv6 To Long`, `JSON`, `XML`.
  Evidence: `Plugins/Transformations/Input/*.php`, `Output/*.php`, root `Text_Plain_*.php` (`getMIMEType`/`getMIMESubtype`/`getName` at the cited method blocks).

- **FR-PLG-056 Transformation wrapper route** (added in review wave 1) — Binary/derived content for `ImageLink`, `Inline`, `Download` and the upload preview is served by `/transformation/wrapper` (`Controllers/Transformation/WrapperController`). Accepted request keys: `cn` (download filename), `ct` (content type), `sql_query`, `transform_key` (column), `where_clause` (+ `where_clause_sign`), `newWidth`, `newHeight` (integers capped at 2000), `resize` (`jpeg` or `png`). The where clause must carry a valid signature (`Core::checkSqlQuerySignature`), otherwise "There is an issue with your request."; without a where clause the first row of the table is used; no row -> empty response. Content type: `ct` if given, else the stored column mimetype (`_` -> `/`) plus an optional `; charset=` option, else `application/octet-stream`; content is sent with download headers; for a content type containing `html` the value is HTML-escaped before output. Resizing: ratio is kept so the result fits within `newWidth` x `newHeight`; JPEG quality 75; PNG default; the source is read with GD (`ImageWrapper::fromString`), failures produce an empty body.
  Evidence: `Controllers/Transformation/WrapperController.php:30-190`.
  Verification: request `/transformation/wrapper` for an image column with a valid signed `where_clause_sign` and `resize=jpeg&newWidth=5000&newHeight=5000` and assert an image no larger than 2000x2000 and `Content-Type: image/jpeg`; alter one character of `where_clause_sign` and assert "There is an issue with your request."; omit the where clause and assert the first row is used. (added in review wave 2)

- **FR-PLG-057 Availability matrix** (added in review wave 1) — The enumeration (`Plugins::getPlugins`) shall list: Export - all 15 except `ExportPdf` (needs TCPDF + curl) and `ExportXml` (needs a selected database); Import - `ImportLdi` only at `table` scope, all others always; Schema - `SchemaPdf` only with TCPDF, `SchemaDia`/`SchemaEps`/`SchemaSvg` always. The ordering of the dropdown is the case-insensitive order of the localized plugin names (FR-PLG-006). Note the import controller additionally hard-codes the accepted format list (`csv, ldi, mediawiki, ods, shp, sql, xml`), so a newly added import plugin must be registered there as well (04-io-formats FR-IOX-038).
  Evidence: `Plugins.php:119-150`; `Plugins/Export/ExportPdf.php:334-337`; `ExportXml.php:551-557`; `Import/ImportLdi.php:185-190`; `Schema/SchemaPdf.php:128-131`; `Controllers/Import/ImportController.php:244-248`.
  Verification: list the plugins at server scope: Export shows 14 formats (no XML) or 13 without TCPDF/curl; at database scope 15 or 14; Import shows 6 formats at server and database scope and 7 (with `ImportLdi`) at table scope; Schema shows 4 formats, 3 without TCPDF. (added in review wave 2)

- **FR-PLG-058 Stored-name case round trip** (added in review wave 1) — `setMime` lowercases the `mimetype` and the (output) `transformation` before storing them, and `getMime` restores capitalization with `fixUpMime` (JPEG/PNG special-cased, words after `_`/digits capitalized, spaces removed). Input transformation names are stored unchanged. A reimplementation must reproduce a deterministic round trip; as read from the code, an output transformation whose file name contains an inner capital (the only bundled case is the root class `Text_Plain_PreApPend`, which restores as `Text_Plain_Preappend.php`) will not match the file on a case-sensitive file system and is then silently not applied (not executed to confirm).
  Evidence: `Transformations.php:250-271, 283-336, 352-380`; `Plugins/Transformations/Text_Plain_PreApPend.php`.
  Verification: save an output transformation `Text_Plain_PreApPend` for a column, reload the table structure page and assert the displayed name is `Output/Text_Plain_Preappend.php` (stored lower-cased, restored by `fixUpMime`); on a case-sensitive file system assert the transformation is not applied at browse time (this was derived from the code and not executed during the review), while `Text_Plain_Json` and `Text_Plain_Bool2Text` round-trip unchanged. (added in review wave 2)

### 6.10.4 Security, data and interface additions

- **SEC-PLG-007 Output-escaping contract of transformations** (added in review wave 1) — Output transformations return HTML. Those that embed the column value shall HTML-escape it (`DateFormat`, `Download`, `ImageLink`, `Inline`, `LongToIPv4`, `PreApPend`, `Substring`, `TextImageLink`, `TextLink`, `JSON`, `XML`, `SQL` via the formatter). Deliberate exceptions: `Formatted` (raw HTML, contained by a sandboxed iframe with `"` replaced by `'`), `Bool2Text` (returns option text), `External` when its output-escape option is not 1/2, and `Hex`/`IP` converters (output is hexadecimal or numeric text). A new transformation must declare which of the two classes it belongs to.
  Evidence: files cited in FR-PLG-037 to FR-PLG-051.

- **SEC-PLG-008 Wrapper hardening** (added in review wave 1) — Requests to the transformation wrapper shall be accepted only for rows addressed by a signed where clause, and the resize dimensions shall be clamped to at most 2000 px each (`Controllers/Transformation/WrapperController.php:55-95`). Link-producing transformations (`TextLink`, `TextImageLink`) shall pass the generated URL through `Sanitize::checkLink` and degrade to plain escaped text when it fails; `TextLink`/`ImageLink` links use `rel="noopener noreferrer"`.
  Evidence: as cited.

- **DATA-PLG-007 Option property API (PluginPropertyItem / OptionsProperty*)** (added in review wave 1) — The contract of the properties model shall be: `PluginPropertyItem` (`text`, `extension`, `mimeType`, `options` (a root group), `optionsText`, derived `forceFile`; `getPropertyType()`); `OptionsPropertyItem` (`name`, `text`, `force`); `OptionsPropertyOneItem` adds `values` (array key => label, for radio/select), `doc` (array of 1 to 3 elements, see FR-PLG-024), `len` (maximum input length), `size` (input width); groups (`OptionsPropertyGroup` = `Countable`, `addProperty`/`removeProperty`/`getProperties`/`getNrOfProperties`) are `OptionsPropertyRootGroup`, `OptionsPropertyMainGroup` and `OptionsPropertySubgroup` (adds `subgroupHeader`, an item rendered before the subgroup). Leaf items: `BoolPropertyItem`, `TextPropertyItem`, `NumberPropertyItem`, `RadioPropertyItem`, `SelectPropertyItem`, `HiddenPropertyItem`, `MessageOnlyPropertyItem`, `DocPropertyItem`. `getItemType()` returns the discriminator; `force` on a Bool item names another Bool item that must stay checked when this one is unchecked (the interlock script in FR-PLG-023).
  Evidence: `Properties/Plugins/PluginPropertyItem.php:20-170`; `Properties/Options/OptionsPropertyItem.php`, `OptionsPropertyOneItem.php:21-150`, `OptionsPropertyGroup.php`, `Groups/*.php`, `Items/*.php`.

- **DATA-PLG-008 Transformation persistence record** (added in review wave 1) — Per column the Configuration Storage table `column_info` (db_name, table_name, column_name) stores `comment`, `mimetype`, `transformation`, `transformation_options`, `input_transformation`, `input_transformation_options`. Saving all-empty values deletes the record unless a comment remains; mimetype and output transformation are lower-cased on write (FR-PLG-058). The table is reached through the control connection and only when the browser-transformation feature of the relation parameters is configured (DEP-PLG-002).
  Evidence: `Transformations.php:283-336, 352-448`.

- **INT-PLG-005 Plugin parameter contexts** (added in review wave 1) — `$plugin_param` shall carry: for export `{export_type: server|database|table|raw, single_table: bool}`, for import the scope string `server`, `database` or `table` (or `query`/`queryfile` for the SQL box), for schema `null`. Plugins read it in `setProperties()` and `isAvailable()` to vary their options (for example CSV import shows the new-table/new-database fields and the analyzer only when the scope is not `table`).
  Evidence: `Plugins.php:57-109`; `Plugins/Import/ImportCsv.php:59-130`; `Controllers/Export/ExportController.php:231-236`.

- **INT-PLG-006 UI integration points of the property tree** (added in review wave 1) — The plugin chooser/option panels are consumed by the export page (`Export/Options`), server/database/table import pages and the Designer schema-export dialog (`Database/Designer.php:131-144`, schema default `Plugins::getDefault('Schema','format')`). Option names are namespaced `<plugin>_<option>` so that panels of different formats can coexist in one form and all be submitted (cf. 04-io-formats FR-IOX-087).
  Evidence: `Export/Options.php:134-189`; `Controllers/Server/ImportController.php:54-98`; `Database/Designer.php:131-144`.

- **CPT-PLG-006 MIME naming convention** (added in review wave 1) — The user-visible MIME of a transformation is `Type/Subtype` (for example `Text/Plain`, `Image/JPEG`), the stored form uses `_` (`Text_Plain`), and the file/class name is `Type_Subtype_Name` where `Name` is the third underscore part (FR-PLG-029). Files with fewer than three parts are treated as plain MIME placeholders (`empty_mimetype`).
  Evidence: `Transformations.php:155-177, 250-271`.

- **UI-PLG-003 Widget details** (added in review wave 1) — Checkbox options post the literal value `something` when checked (any non-empty presence means true; absence means false); number items render `min="0"` with no maximum; text items honor `size` and `maxlength`; hidden items post their default; message-only items render raw (already-translated) text. As read from the code, `DocPropertyItem` rendering prints the class name via `echo` (a leftover defect) and `MessageOnlyPropertyItem` opens an `<li>` that is not closed in its own branch; a reimplementation shall render these cleanly.
  Evidence: `Plugins.php:385-542` (Bool `:394-420`, Doc `:422-424`, Hidden `:425-433`, Number `:513-532`).

- **NFR-PLG-004 Wrapper resource bound** (added in review wave 1) — Image resizing in the wrapper shall be bounded in memory by the 2000 x 2000 px clamp on the requested thumbnail size (the source image is still decoded in full by GD).
  Evidence: `Controllers/Transformation/WrapperController.php:55-70, 140-175`.

## Gaps & open questions

1. **Naming mismatch (requirement-set intake).** The analysis brief names `PluginManager`, `PluginInfo`, `Plugins\Charsets`, `PropertyItem/Css`. In 5.2.3 these exist under different names: manager = `LegacyAdmin\Plugins`; info = `Properties\Plugins\PluginPropertyItem` tree; charsets = `LegacyAdmin\Charsets` (charset/collation metadata, not plugin code). No `Css` property item exists in 5.2.3 (only `Bool/Doc/Hidden/MessageOnly/Number/Radio/Select/Text` in `libraries/classes/Properties/Options/Items/`). Confirm whether the desired new-system port must reintroduce the 4.x `CssPropertyItem` concept or whether skipping it is acceptable.
2. **No runtime plugin toggling.** Plugin set is determined solely by file presence + `isAvailable()`; there is no per-plugin admin enable/disable. Should the re-engineered system add a toggle?
3. **`getDefault` / `checkboxCheck` rely on super-globals.** Untestable coupling to `$_GET`/`$_REQUEST`/`$GLOBALS['timeout_passed']`; open question how much of FR-PLG-016/17 should be preserved as-is vs. refactored with injected request state.
4. **Options whitelist maintenance.** The POST-parameter allow-list in `Controllers/Export/ExportController.php` enumerates options only for SQL/CSV/LaTeX etc.; adding a plugin requires editing that controller list (FR-PLG-014). A spec follow-up should decide whether new-system option ingestion is generic (driven by the property tree) or keep the whitelist approach.
5. **Input vs output options asymmetry.** `column_info` stores both `transformation(_options)` and `input_transformation(_options)` but there is no UI-level metadata about option arity per plugin beyond `getInfo()` prose; question: should new system formalize per-plugin option signatures?
6. **`TransformationsPlugin` in legacy root or `Abs/` classes.** Legacy root-level files `Text_Plain_Link.php`, `Text_Plain_Longtoipv4.php`, `Text_Plain_PreApPend.php`, `Text_Plain_Substring.php` coexist with `Abs/`/`Output/` variants; confirm whether they must remain (compat) or can be pruned in the port.
7. **Charset-plugin omission.** `Charsets` in 5.2.3 (value objects + listing helpers) is excluded from plugin enumeration; if a "Plugins\Charsets" contract is desired (as in older LegacyAdmin ≥4.8 export/import charset dropdowns), this must be specified separately (not extractable from 5.2.3 plugin framework).
8. **Schema plugin property inheritance.** (partly resolved in review wave 1) Schema options per format are now listed in 04-io-formats FR-IOX-097; `SchemaPluginProperties` itself remains pattern-identical to `ImportPluginProperties`.
9. **Two-factor / auth plugin surface completeness.** Only the abstract contracts were inspected; `AuthenticationCookie` internals (session crypto, `showLoginForm()`) and per-two-factor implementations are out of scope for 06-plugins and likely belong in an auth-specific spec.
10. **Test-suite as executable spec.** `test/classes/Plugins/Transformations/TransformationPluginsTest.php` encodes concrete expected behaviors (e.g. nowrap semantics, `getScripts`, per-class transformation cases) that this document summarizes only at requirement level; a follow-up could mine that suite for exhaustive per-plugin acceptance criteria.
