## 1. Shell and layout

- **FR-UIX-001** — The system shall render every page from a single HTML shell composed of a navigation panel, a floating top menu bar, a console container, and a `#page_content` div that contains messages, the main panel and modal includes. — templates/header.twig:24-60, templates/footer.twig:1-22
- **FR-UIX-002** — The document root element shall carry `lang="{{ lang }}"` and `dir="{{ text_dir }}"` so that the interface language direction (rtl/ltr) is set on every page. — templates/header.twig:2
- **FR-UIX-003** — The head shall include: charset meta, viewport meta (`width=device-width, initial-scale=1`), a `referrer: same-origin` meta, `robots: noindex,nofollow,notranslate`, a favicon, jQuery-UI CSS, CodeMirror CSS (lib + hint + lint) and the theme CSS chosen per text direction (`theme.css` or `theme.rtl.css`), each versioned with the application version string for cache busting. — templates/header.twig:4-20
- **FR-UIX-004** — The navigation panel (`#pma_navigation`) shall be marked `d-print-none` (excluded from printing) and carry `data-config-navigation-width` for the saved panel width. — templates/navigation/main.twig:2
- **FR-UIX-005** — The navigation header shall contain: a configurable logo (`logo.is_displayed`, optional link and image source, falling back to an `<h1>LegacyAdmin</h1>`), and a link bar (`#navipanellinks`) with Home, Log out (title varies by auth type: "Log out" vs. "Empty session data" for auth `config`), LegacyAdmin documentation, MySQL/MariaDB documentation (selected by `is_mariadb`), navigation settings (hidden unless enabled), and reload-navigation actions; all doc links open in a new tab with `rel="noopener noreferrer"`. — templates/navigation/main.twig:8-50
- **FR-UIX-006** — The navigation header shall show a server choice select (`#serverChoice`) only when more than one server is configured. — templates/navigation/main.twig:52-56

- **FR-UIX-008** — The top menu (`#topmenucontainer`) shall be a Bootstrap 5 navbar with a hamburger toggler (`data-bs-toggle="collapse"`, localized `aria-label` "Toggle navigation") and a `#topmenu` nav list; each tab is a `disableAjax` link carrying an icon, and the active tab gets `.active` plus a visually hidden "(current)" marker. — templates/top_menu.twig:1-19
- **FR-UIX-009** — When a server is selected and the menu is enabled, the header shall render `#page_nav_icons` containing the page-lock icon, the page-settings (cog) icon and a "goto pagetop" anchor, all `d-print-none`. — templates/header.twig:39-47
- **FR-UIX-010** — The footer shall contain the `#selflink` (opens the same page in a new LegacyAdmin window; icon or text depending on the `TabsMode` icon setting), an error container `#pma_errors`, and the script stack. — templates/footer.twig:5-21
- **FR-UIX-011** — The home screen shall be a card-based layout (Bootstrap grid, `container-fluid`) with sections that include demo-server notice, general settings (server selection, change password link, connection-collation select), database/server status, and a themes list. — templates/home/index.twig:9-70, templates/home/themes.twig:1-18
- **FR-UIX-012** — The themes screen shall present each theme as a card showing `themes/{id}/screen.png` as screenshot plus name and version, with a "Take it" submit button posting to `/themes/set` as a `disableAjax` form (i.e., a full page reload). — templates/home/themes.twig:1-13
- **FR-UIX-013** — The login form shall use `#login_form` with hidden `set_session`/`session_timedout` fields, username/password inputs with explicit autocomplete hints (`username`, `current-password`) and `spellcheck=false`, a language selector marked `lang="en" dir="ltr"`, and `autocomplete="off"` on the form when disabled by configuration. — templates/login/form.twig:47-89, 32-41
- **FR-UIX-014** — A `<noscript><style>html{display:block}</style></noscript>` shall always un-hide the page (overriding the `#cfs-style` `html{display:none}` rule emitted when third-party framing is disallowed), and when `is_warnings_enabled` is true (it is switched off on the login page by `disableWarnings()`) a `<noscript>` error "Javascript must be enabled past this point!" shall be rendered. — templates/header.twig:9-11, 22, 33-37, libraries/classes/ResponseRenderer.php:517 (corrected in review wave 1)
- **FR-UIX-015** — The `is_ajax` template flag (true when request parameter `ajax_request` is non-empty) selects full-page rendering (navigation + footer wrappers) versus fragment rendering; it is NOT a JavaScript-availability test. Without JavaScript the server still renders the full HTML page, but navigation tree, console, page settings, modals and all AJAX behaviour are inoperable, so the product is effectively JavaScript-dependent (see FR-UIX-110). — templates/navigation/main.twig:1,72, templates/footer.twig:1-4,44, libraries/classes/ResponseRenderer.php:175 (corrected in review wave 1)

## 2. AJAX ("no reload") navigation and page lifecycle

- **FR-UIX-016** — The system shall intercept all document-level link clicks and form submits generically and convert them into AJAX page requests: parameters `ajax_request=true&ajax_page_request=true` plus form serialization or anchor `data-post`, with `history.pushState` (or `replaceState` when an aborted request is re-used) for URL tracking. — js/src/ajax.js:228-348, 319-328, 890-891
  Verification: Jest/Selenium: click an in-page link and submit a form; assert the XHR carries `ajax_request=true&ajax_page_request=true`, `history.length` grows and the URL changes without a full document load.
- **FR-UIX-017** — The request handler shall let the browser act natively (skip AJAX) for: shift/ctrl/meta-clicks, links with a `target` attribute, links styled `ajax`/`disableAjax`, `#`-anchors, `mailto:` links, and jQuery-UI-datepicker pager links. — js/src/ajax.js:232-249
  Verification: Selenium: ctrl-click, shift-click, `target=_blank`, `a.disableAjax`, `#` and `mailto:` links must not issue an AJAX page request.
- **FR-UIX-018** — While a page load is in progress the system shall abort an existing in-flight link request (showing "Aborted request" message), or refuse concurrent form submissions, and shall scroll to top and show a processing message. — js/src/ajax.js:271-296, 314-347
- **FR-UIX-019** — On a successful AJAX response the system shall: tear down old page scripts, optionally reload navigation (`data.reloadNavigation`), replace `title`, replace the floating menu (`data.menu`), purge unknown body children ( whitelist: modals, `#pma_navigation`, `#floating_menubar`, `#page_nav_icons`, `#page_content`, `#selflink`, `#pma_header/footer`, `#pma_demo`, `#pma_console_container`, `#prefs_autoload`), replace `#page_content` with `data.message`, apply SQL highlighting, refresh `CommonParams`, load `data.scripts`, re-fire onload events, and update `#selflink` href (with special-case rewrite of import/chart/gis-visualization URLs to their canonical pages). — js/src/ajax.js:477-605, 533-546
  Verification: Selenium: navigate between two pages and assert `#page_content` replaced, `<title>` updated, console and navigation DOM nodes preserved and `#selflink` rewritten for import/chart pages.
- **FR-UIX-020** — Failed AJAX responses shall show `data.error` in a message box, append an `#ajaxError` div, scroll to the bottom of the page, mark the input named by `data.fieldWithError` with class `error`, and support `Functions.handleRedirectAndReload` server-directed redirects. — js/src/ajax.js:606-621
- **FR-UIX-021** — The page-lock feature shall latch a lock icon (`#lock_page_icon`) whenever any input of a `form.lock-page` has an unsaved change (hash comparison of value/checked state, including CodeMirror content) and ask for confirmation ("confirm navigation" dialog) before navigating away. — js/src/ajax.js:151-211, 260-266, 820-843
- **FR-UIX-022** — Session-expired logins shall be retried inside a modal: the login POST is routed through a dedicated `loginResponseHandler` that swaps the CSRF token into all `input[name=token]`, removes/re-inserts `#pma_errors`, optionally auto-submits the error report form for `sendErrorReport='always'`, and re-enables or fully reloads the page if the logged-in user changed. — js/src/ajax.js:341-342, 359-450
- **FR-UIX-023** — The script loader shall download only scripts not already cached client-side, appended as `<script>` tags from `js/dist/<name>` (or the vendor path verbatim) with `?v=version` and `async=false`, firing per-file `onload_<hash>` and `teardown_<hash>` document events; the loader resets its cache when the server version changes. — js/src/ajax.js:628-757 (esp. 675-709, 744-756)
  Verification: load a page, record script requests, navigate to a second page and assert each `js/dist/<name>.js?v=<version>` is requested once; change the version and assert the cache is reset.
- **FR-UIX-024** — Initial page load shall register the pre-rendered scripts with `AJAX.scriptHandler.add(name, has_onload)` and fire their `onload` events on DOM ready, so both full and AJAX-loaded pages share the same lifecycle. — templates/scripts.twig:7-23
- **FR-UIX-025** — Back/forward navigation shall be handled via `popstate`: the state silently stores `{url, menu}` and a popstate re-requests the URL through the AJAX response handler. — js/src/ajax.js:849-884
- **FR-UIX-026** — Fatal AJAX-level errors (non-aborted) shall produce a structured error message (status code + statusText + connection hint) styled as an alert, and `git-revision` endpoint errors shall be ignored. — js/src/ajax.js:897-929

## Gaps & open questions

1. **Compiled CSS missing in this tree** — `themes/*/css/` contains no files here; header references `css/theme.css`. The release must ship compiled CSS; the SCSS-only tree means the legacy frontend cannot render styles as-is. Confirm the downstream project must reproduce the build step (sass + rtlcss + Bootstrap variables).
2. **`js/dist/` is empty** — all page scripts referenced as `js/dist/<file>` by `scripts.twig`/`AJAX.scriptHandler.appendScript` are absent; the packaging/build (Babel `js-compile` and Sass `css-compile` via `yarn build`; there is no webpack configuration in the tree) has not been run. Whether the target system keeps the same on-the-fly script loading or bundles single-file (e.g., Vite/webpack) is open.
3. **Web workers** — the requirement "syntax highlighting auto?" cannot be confirmed as true Web Workers usage (only CodeMirror's timer-based internal highlighter). Treat as constraint/decision point.
4. **"Benchmarks of fetch/rep"** — ambiguous in the source; closest evidence found is replication-section toggling and `BENCHMARK()` documentation link mapping. If requirement means actual benchmark or fetch profiling dashboards (server status monitor plots), a separate spec (07-performance) should be written; current spec covers client-side caching/loading only, pending clarification.
5. **Keyboard shortcuts** (corrected in review wave 1) — the code-derived list is FR-UIX-111; shortcuts registered by third-party libraries (CodeMirror key maps, jQuery-UI dialogs) were not enumerated. Observation: the `d`/`t` arming flags are cleared only via a timer started on keyup, and `s`/`f`/`e`/`h` fire on keydown regardless of Ctrl/Alt/Meta modifiers (modifier combinations such as Ctrl+S/Ctrl+H/Ctrl+F outside inputs may also trigger them) — whether this is intended is an open decision.
6. **RTL completeness** — RTL behavior described, but full RTL audit of all 4 themes (original/metro/bootstrap have their own scss) not performed.
7. **Free-form/pmarc browser support details** — the set of browsers tested by upstream (browsers-devices page) is external to the tree.
8. **Accessibility** (ARIA, screen-reader) — only aria-labels on the navbar toggler and hamburger found; no dedicated a11y audit in 5.2.3 templates. Open question whether target product requires WCAG parity.
9. **Legacy jQuery / `$.validator` plugin names (`uiTooltip` vs `tooltip`)** — code uses both names as feature-detection fallback; behavior with modern jQuery not verified.
10. **Meta referrer/robots implementation** on the "redirect" template (`templates/javascript/redirect.twig`) was not inspected.
