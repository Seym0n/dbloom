## 3. Export: buffering, compression, save-to-server

- **FR-IOX-024** — All export output shall funnel through a single `outputHandler()` that (a) buffers into a dump buffer when compression is active or save-on-server is enabled, (b) echoes immediately for unsaved file exports, and (c) HTML-escapes (`htmlspecialchars`) for text-view mode.
  Evidence: `libraries/classes/Export.php:128-218 (branches at 137-179, 180-211, 212-215)`.

- **FR-IOX-025** — The system shall support ZIP and GZIP output compression, offered only when the corresponding PHP functions exist (`gzcompress`, `gzencode`) and the config allows them (`cfg['ZipDump']`, `cfg['GZipDump']`); selecting a compression forces buffered output.
  Evidence: `libraries/classes/Controllers/Export/ExportController.php:245-252, 284-287`; `libraries/classes/Export.php:494-506`.
  Verification: set `ZipDump` and `GZipDump` to false and assert no compression choice is offered; set both true and export with gzip, then assert the file starts with bytes `1F 8B` and the name ends in `.gz`; repeat with zip and assert the signature `PK`. (added in review wave 2)

- **FR-IOX-026** — Under GZIP the system shall "compress on the fly" when `cfg['CompressOnFly']` is set: once the buffer exceeds the computed memory budget it shall charset-convert, `gzencode()`, and flush (echo or fwrite-to-server-file), then reset the buffer.
  Evidence: `libraries/classes/Controllers/Export/ExportController.php:385-390`; `libraries/classes/Export.php:140-172`.

- **NFR-IOX-027** — The export memory budget shall be derived from `ini_get('memory_limit')` (with k/M/G suffix parsing, default 2 MB when unset or `-1`), minus a 1.5 MB overhead reserve, reduced to 1/8 for compression headroom. (corrected in review wave 1)
  Evidence: `libraries/classes/Export.php:257-286`.
  Review wave 1 correction (exact arithmetic): `memory_limit` is parsed from `ini_get` with suffix `k`/`m`/`g` (case-insensitive, 1024-based); empty or `-1` yields 2 097 152 bytes; the 1 500 000-byte (decimal, not 1.5 MiB) reserve is subtracted only when the limit exceeds 1 500 000; the result is divided by 8 (the code comment says "1/3", the code uses 8). Example: unlimited (-1) gives (2 097 152 - 1 500 000) / 8 = 74 644 bytes of buffer before an on-the-fly gzip flush. Note: `cfg['MemoryLimit']` defaults to `'-1'` and is applied by `ini_set` before this computation, so the 2 MB fallback is the normal case with default configuration (`Export.php:257-286`; `ExportController.php:353-358, 385-390`; `config.default.php` `MemoryLimit`).
  Verification: unit-test `Export::getMemoryLimit()` with `memory_limit` values `''`, `-1`, `512k`, `128M`, `2G`; expected: 74644, 74644, 65536 (no reserve subtracted because 524288 is below 1 500 000), 16589716, and (2147483648 - 1500000) / 8. (added in review wave 2)

- **NFR-IOX-028** — The system shall raise PHP execution time via `Util::setTimeLimit()` and apply `cfg['MemoryLimit']` (ini_set) for the export request, and shall register a shutdown hook that stamps `$_SESSION['pma_export_error']` when the last error mentions "execution time" so the client can detect timeout-truncated exports.
  Evidence: `libraries/classes/Controllers/Export/ExportController.php:353-358`; `libraries/classes/Export.php:80-89`.

- **FR-IOX-029** — An AJAX-endpoint `/export/check-time-out` shall report `timeout` when the shutdown flag from FR-IOX-028 is present (clearing it), else `success`.
  Evidence: `libraries/classes/Controllers/Export/CheckTimeOutController.php:11-23`; route group `/export` in `libraries/routes.php:109-122`.

- **FR-IOX-030** — Saving on server shall be available only when `cfg['SaveDir']` is non-empty; the system shall reuse the user-configured SaveDir via `Util::userDir()`, forbid `/` `\` in filenames (replaced with `_`), block overwrite unless the overwrite option is set, refuse non-writable files or failed `fopen` with named error messages, verify each write byte count ("Insufficient space to save the file %s.") and report success ("Dump has been saved to file %s.").

- **FR-IOX-031** — When compression is requested the final filename shall gain `.zip`/`.gz`, the MIME type shall be switched to `application/zip` / `application/x-gzip`, and the plugin's extension shall be appended when absent (case-insensitive check).
  Evidence: `libraries/classes/Export.php:297-328`.

- **FR-IOX-032** — ZIP export shall create a single-entry (or multi-entry for separate-files) archive via the ZipExtension; separate-files mode (`as_separate_files`, zip-only) shall buffer each table/db section into named objects (`saveObjectInBuffer`) and compress the collection into one archive.

- **SEC-IOX-033** — The generated download filename shall be sanitized (`Sanitize::sanitizeFilename`, dots removed at creation to prevent path traversal / remote code execution) before being placed in download headers; `url_rewriter.tags` shall be reset for file downloads to avoid HTML anchor rewriting. (corrected in review wave 1)
  Evidence: `libraries/classes/Export.php:384-385`; `libraries/classes/Controllers/Export/ExportController.php:429-436`.

### 12.3 Import specifics

- **FR-IOX-088 (CSV import parsing and validation)** (added in review wave 1) — Before parsing, `\n`, `\t` and `\r` two-character escapes in terminator, enclosure, escape character and line terminator shall be expanded. Parameter validation (each failure shows "Invalid parameter for CSV import: <Columns terminated with | Columns enclosed with | Columns escaped with | Lines terminated with>" via `mysqlDie`): terminator must be non-empty (multi-character allowed); enclosure at most 1 character (empty = unenclosed); escape at most 1 character; line terminator exactly 1 character or the literal `auto` (CR, LF or CRLF; a trailing CR needs a look-ahead and defers to the next chunk). Value rules: an unquoted field equal to `NULL` becomes SQL NULL, a quoted `NULL` is the text "NULL"; when escape equals enclosure a doubled enclosure stands for one literal enclosure; a field ends at the terminator or the line end; a missing final field yields an empty string. Errors: "Invalid format of CSV input on line %d." (deadlock guard when no parse progress is made, or unparsable trailing data at EOF) and "Invalid column count in CSV input on line %d." (value count differs from the required columns; only a single trailing `;` value is tolerated as an Excel quirk). Each data row is written as `<sql_template>'v1','v2',NULL...)` with `escapeString` applied to every non-NULL value (all values are quoted strings, the server converts types). `partial_import` > 0 limits the import to that many rows (one more is read when the first row holds column names); `csv_col_names` (default false) takes the first row as column names, right-trimmed. For an existing table the optional `csv_columns` list (comma separated, unquoted) selects the target columns; an unknown column yields "Invalid column (%s) specified! ### 12.6 Additions from review wave 2

- **FR-IOX-100 (DML simulation, /import/simulate-dml)** (added in review wave 2) — The system shall offer a dry-run that reports how many rows an `UPDATE` or `DELETE` would affect without changing data. Route `POST /import/simulate-dml` with the query text (`sql_query`) and the statement delimiter (`sql_delimiter`, required). The text is lexed with the given delimiter (comments are dropped) and parsed; the first parser error is returned as an error message with `sql_data = false`. Every statement must be a single-table `UPDATE` or `DELETE` without JOIN, otherwise the error is "Only single-table UPDATE and DELETE queries can be simulated." For `DELETE` the probe is `SELECT * FROM <table> [WHERE ..] [ORDER BY ..] [LIMIT ..]`; for `UPDATE` it is `SELECT * FROM (SELECT *, <new value> AS `col `new`` ... FROM <table> [WHERE ..] [ORDER BY ..] [LIMIT ..]) AS pma_tmp WHERE NOT (old columns) <=> (new columns)`, i.e. only rows whose values would really change are counted; when a column is assigned twice the last assignment wins. The response lists, per statement, the formatted statement, the number of matched rows (0 if the probe fails) and a signed `/sql` link (`sql_signature`, SEC-DTB-001) that shows the matched rows. It is triggered by the "Simulate query" button (`#simulate_dml`) of the SQL tab, which posts the editor text and the delimiter field and shows the result in a modal (`js/src/sql.js:736-775`, `templates/sql/query.twig:214-218`); executing the DML is a separate action.
  Evidence: `libraries/routes.php:123-125`; `libraries/classes/Controllers/Import/SimulateDmlController.php:54-111`; `libraries/classes/Import/SimulateDml.php:50-143`; `js/src/sql.js:736-775`.
  Verification: in a table with 10 rows submit `UPDATE t SET c = c WHERE id < 5` and assert 0 matched rows (no value changes), `UPDATE t SET c = c + 1 WHERE id < 5` and assert 4 (for ids 1-4), `DELETE FROM t LIMIT 3` and assert 3, a two-table `UPDATE` and assert the single-table error, and assert that the table content is unchanged after every call.
